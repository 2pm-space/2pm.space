# Messenger・Zalo・Telegram・ウェブサイトチャットのための AI Inbox

> Messenger、Facebook コメント、Zalo、Telegram、Web チャットに 1 つの共有受信箱から回答。商品を理解した AI エージェントが応対し、どのスレッドにも「AIを停止」スイッチがあります。

## 販売につながるすべての会話を、 1つの AI 受信箱に

Messenger、Telegram、ウェブサイトチャット、個人 Zalo が1つの共有キューに集まります — 商品を把握し、お客様を覚えている AI エージェントが回答し、チームがスレッドを担当したいときはすぐに身を引きます。

## 4つのチャネルを、1つのキューに

お客様がすでに連絡してくる場所で — それぞれ、ほかのチャネルにはない機能を備えています。

### Messenger

*ダイレクトメッセージとページへのコメント*

- 接続したすべてのページを1つのキューに
- 投稿へのコメントには、公開返信かプライベート返信で対応
- 広告からの流入情報と商品カードをスレッド内に表示
- ページを追加すると、既存の履歴も取り込み

### Telegram

*自社ボット、個人チャット、グループ*

- 自社のボットに、選んだエージェントが応答
- グループチャットでも、メンバーごとに発言者を区別
- 写真、ファイル、ボイスメッセージ — 音声はテキストに文字起こし

### ウェブサイトウィジェット

*自社サイトに置くウィジェット*

- script タグ1つだけ。許可したドメインでのみ動作
- 自社のカラー、あいさつ、ランチャー、クイック返信
- チャット前フォーム、8言語対応、デバイスごとの配置

### 個人 Zalo

*自分のアカウントを QR コードで接続*

- QR コードでログイン — Official Account は不要
- 1対1のチャットもグループチャットも同じキューに
- スレッドから電話番号で友だち申請

ほかにも接続： Pancake · カスタム API — Webhook の受信と送信 · Zalo Official Account（近日対応）

## 最初のメッセージからお礼まで

お客様がどのチャネルからでもメッセージを送ると、エージェントが相談に乗り、注文を受け、配送を手配し、お礼を伝えます — 会話の流れが変わっても、どちらに進むべきかを判断します。

**お客様がチャット**

- **Messenger:** *青いの、まだ在庫ありますか？*
- **Telegram:** *ダナンまで配送できますか？*
- **ウェブサイトウィジェット:** *これ2つだといくらになりますか？*
- **個人 Zalo:** *代引きで払えますか？*

### 2pm AI が接客

すべてのチャネルの裏側に、1つのエージェント。ワークスペースが知っていることをすべて活用します。

- **ナレッジ** — ドキュメントやカタログから回答。商品写真も含めて
- **スキル** — 自社の営業プレイブック — 何を聞き、何を提案し、どんな口調で話すか
- **ツール** — 会話の途中で、商品、過去の注文、送料を調べます
- **メモリ** — お客様が前回話したことを覚えています
- **Customer 360** — お客様が使ったすべてのチャネルを、1つの履歴に
- **ガードレール** — すべての返信を、言ってよいこと・してよいことの範囲内に保ちます

1. **内容を確認** — 商品、電話番号、配送先住所をお客様と確認し合います。 `住所を保存`
2. **注文を作成** — カタログの価格で受注を作成 — チームが確定する下書きにするか、そのまま確定します。 `SO-2026-48213`
3. **COD 配送を手配** — 代引き金額を付けて Viettel Post に手配するか、自社の配送業者向けに納品書として残します。 `COD · 追跡番号`
4. **お礼を伝える** — 配達完了が報告されると、イベントルールがお礼を送信 — スレッドの内容から書くか、テンプレートを使います。 `配達済み → お礼済み`

**その途中で**

- **電話番号を教えてくれたら → Zalo で友だち追加.** 番号は連絡先に紐づけられ、個人 Zalo から友だち申請を送信 — 間隔を空けて、午前8時から午後8時の間に。承認されると、Zalo のチャットも同じ顧客にまとまります。 `+84 ••• 412 → Zalo`
- **返信が途絶えたら → ケアがフォローアップ.** ケアエージェントがスレッドを読み、設定した無応答時間の後にフォローアップ — 送信しない時間帯を避け、1人あたりの上限を守り、チャネルのメッセージ送信期間内に送ります。 `無応答2時間 → フォローアップ`
- **担当者を求められたら → チームが入る.** エージェントがスレッドを開くプッシュ通知をチームに送ります。誰でもそこで返信でき、AI を停止してスレッドを引き取ることもできます。 `通知 → AI 停止`
- **スパムや迷惑行為があれば → エージェントが返信を停止.** そのスレッドの AI とケアをオフにし、チームに1行の理由を残します。受信箱から誰でもオンに戻せます。 `AI オフ · 理由を記録`

## ページを接続して、エージェントが動き出すまで

3ステップで、最初の会話にその日のうちに回答します。

1. **チャネルを接続** — Facebook ページ、Zalo アカウント、Telegram ボット、またはウェブサイトウィジェットを接続します。既存の履歴も取り込まれるので、受信箱は空のリストではなく、すでにある会話から始まります。
2. **エージェントを配置** — どのエージェントがどのチャネルで答えるかを選び、必要なドキュメントとツールを渡します。お客様の連続したメッセージが途切れると、エージェントは自動で返信します。待ち時間、チームに任せるタグ付きの会話、テスト中は返信をアプリ内にとどめるサンドボックスモードを設定できます。
3. **見守り、介入し、改善する** — すべての返信には、その実行（ツール呼び出しとコスト）が実行ログとして残ります。人が必要なスレッドでは AI を停止し、返信を評価・改善しましょう。修正はすぐにエージェントに反映され、後の学習にも使われます。

## 受信箱を実際に回すチームのために

ページに後付けしたチャットボットではありません — チームとエージェントが一緒に回す共有キューです。

### 最前線に立つエージェント

エージェントの1つをチャネルに割り当てると、商品カタログ、ドキュメント、そのお客様について覚えていることを使って、あなたの口調で回答します。ツールも使えるので、「わかりません」と謝る代わりに注文を調べられます。

### もめない引き継ぎ

チームの誰でも会話の途中で返信できます — 同じスレッド、同じ履歴のまま。その返信は、エージェントが書いている途中の回答を取り消しますが、エージェントはオフになりません。「AIを停止」を押すと、誰かが再び有効にするまでスレッドはチームのものになります。人が判断すべき場面では、エージェントは人に任せます。受けた注文は下書きとしてチームの確定を待ち（自動確定を許可した場合を除く）、スレッドを開くプッシュ通知をチームに送ることもできます。

### 5つのスレッドではなく、1人のお客様

連絡先はチャネルをまたいで照合されるため、Facebook のコメント、Messenger での返信、Zalo のメッセージが、1つの履歴を持つ1人のお客様になります — 電話番号、タグ、属性も紐づいた状態で。

### 電話番号を拾って、残す

会話の途中でお客様が入力した番号を検出し、すでに保有している番号と重複を排除して、連絡先に紐づけます — スタッフの番号や転送された引用内の番号といったノイズは、数に入れず除外します。

### スレッドを読んでからのケアフォローアップ

やり取りが途絶えた会話には、履歴を読んだエージェントがフォローアップします — 設定した送信しない時間帯を避け、1人に連絡できる回数の上限を守り、同じ文面の一斉送信には決してしません。

### 行動につながる数字

メッセージ量、応答時間、チャネル別の内訳を1時間ごとに事前集計。日付範囲を変えるたびに1年分のメッセージをスキャンすることなく、ダッシュボードがすぐに開きます。

### メッセージングチャネル

- Facebook Messenger — ダイレクトメッセージ
- Facebook のコメント、プライベート返信にも対応
- 個人 Zalo、QR コードでログイン
- Zalo Official Account — 近日対応
- Telegram ボット
- Pancake アカウント

### 自社の接点

- ウェブサイトウィジェット、どのページにも埋め込み可能
- カスタム API チャネル — Webhook の受信と送信
- 受信箱のイベントで送信する Webhook
- iOS・Android 向けモバイルアプリ
- 会話に直接飛べるディープリンク

### メッセージで扱えるもの

- 写真とアルバム、ファイル、スタンプ
- ボイスメッセージ、検索可能なテキストに文字起こし
- 位置情報、投票、商品カードと広告流入カード
- 引用返信を、返信先のメッセージと並べて表示
- 発言者ごとに識別されるグループチャット

### キューの運用

- 一致した箇所を抜粋表示する全文検索
- チャネル、タグ、種類、返信待ちで絞り込み
- チーム全員で共有するクイック返信
- タグ、ラベル、カスタム属性
- 連絡先パネルに会話の要約

### 管理

- メンバー、ロール、チームごとのチャネルアクセス
- エージェントが受けた注文はスタッフが確定するまで下書きで保持
- エージェントが言ってよいことを制限するガードレール
- スレッドから連絡先をブロック
- 返信ごとの完全な実行ログ、コスト付き

### 取りこぼさない仕組み

- チャネル追加時に履歴を取り込み
- チャネルごとに1時間単位で統計を集計
- 送信しない時間帯と上限を守るケアのフォローアップ
- チャネルの統合、あるアカウントの履歴を別のアカウントにまとめる
- 送信 Webhook の配信ログ

## 初日から変わること

ページに置いたボットと、チームが運用する受信箱の違いです。

| 2pm.space がない場合 | 2pm.space を使うと |
| --- | --- |
| ページごとにタブ、Zalo 用にスマホ、誰が何を言ったかはスプレッドシートで管理 | すべてのチャネルを1つのキューに、お客様ごとに1つの履歴で |
| シナリオどおりにしか答えられず、本当の質問が来た途端に丸投げするボット | ドキュメント、カタログ、ツールを備えたエージェント — そしてワンクリックで人につながる |
| 電話番号は読み流され、手で打ち直され、スレッドが長くなると見失う | 番号を自動で検出し、重複を排除して連絡先に紐づけ |
| フォローアップは同じ文面の一斉送信で、スケジュール次第で何時にでも届く | スレッドを踏まえて書かれたケアメッセージを、送信しない時間帯を避け、1人あたりの上限内で |
| ボットはテキストしか読めないので、ボイスメッセージは再生されず、画像も見られない | 音声は文字起こしされ、画像も理解され、すべて検索可能に |
| 外部スタッフに受信箱を見せるには、ワークスペース全体へのアクセスを渡すしかない | メンバー、ロール、チームごとのチャネル単位のアクセス |

## AI Inbox についてのよくある質問

最初のページをエージェントに任せる前に、チームからよく寄せられる質問です。

### どのメッセージングチャネルを接続できますか？

Facebook Messenger（ページ投稿へのコメントを含む）、Telegram、QR コードでログインする個人 Zalo、Pancake、そして自社サイトに埋め込むチャットウィジェットです。Zalo Official Account にも近日対応します。それ以外はカスタム API チャネルで接続できます。シンプルな Webhook の受信と送信だけで、こちら側に新しいコードは必要ありません。

### AI が自動で返信するのですか？それともスタッフが対応するのですか？

両方です。お客様の連続したメッセージが途切れると、エージェントが新しいメッセージに自動で返信します。チームはいつでも同じスレッドで返信でき、チームの返信はエージェントが書いている途中の回答を取り消しますが、AI はオンのままです。「AIを停止」を押すと、誰かが再び有効にするまでスレッドはチームの担当になり（そのスレッドのケアのフォローアップも止まります）、選んだタグの付いた会話は最初からチームに任せられます。会話の途中で承認を求めるステップはありません。注文については注文そのものがチェックポイントで、エージェントが作る下書きをチームが確定します（自動確定を許可した場合を除く）。

### 同じお客様との会話はまとまりますか？

はい。会話は共通の電話番号やメールアドレスでリンクされるため、Facebook の投稿にコメントし、後日 Zalo でメッセージを送ってきた人も、1つの履歴を持つ1人のお客様として表示されます — 会話中に検出された電話番号、チームが入力したカスタム属性、自社システムから取り込んだプロフィールデータも含めて。

### 画像、ボイスメッセージ、ファイルはどうなりますか？

会話とともに保存され、その場に表示されます — 写真、アルバム、スタンプ、ファイル、位置情報、投票、商品カードは、壊れたリンクではなくそれぞれ本来の形で表示されます。ボイスメッセージは自動で文字起こしされるため、エージェントが実際に読んで回答できる、検索可能なテキストになります。

### どのスタッフがどのチャネルを見られるか管理できますか？

はい。チャネルへのアクセスはメンバー、ロール、チームごとに割り当てられるため、代理店は、ワークスペースのほかの部分を見せることなく、あるクライアントのチームに1つのページだけへのアクセスを渡せます。ワークスペースのほかの機能もすべて同じ権限システムを使っています。

### 返信が途絶えたお客様にフォローアップできますか？

はい — それがケアの役割です。トリガー（N時間動きのない会話、タグ、フィルター）、決して送信しない時間帯、1人に連絡できる回数の上限を設定します。フォローアップの文面は、固定テンプレートの一斉送信ではなく、会話の履歴を使ってエージェントが書きます。
