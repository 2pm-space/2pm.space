# Customer 360 — すべてのチャネルをまたぐ1つの顧客レコード

> 受信トレイの中の Customer 360：会話を開くと、同じ人の他チャネルでのメッセージ（電話番号またはメールで照合）がすでに表示され、検出された番号、リンク済みの顧客、自社システムのライブデータと並びます。

*すべてのチャネルを、1つのレコードに*

## Customer 360 は、 これまでのやり取りから組み上がる

すべてのチャネルの会話、スレッドの途中で拾った電話番号、自社システムのライブデータが、1つの顧客ビューにまとまります — チームが読み、エージェントが回答の拠り所にする、そのビューです。

[無料で始める](https://2pm.space/signup)

## レコードが自動で組み上がる仕組み

データ入力のプロジェクトは不要です。プロフィールは、すでに交わしている会話から導き出されます。

1. **チャネルを接続** — 受信箱が扱うすべての会話がレコードを形作ります。誰が、どこから、何について書いたか。追加で入力するものはありません — 会話があるから、プロフィールがあるのです。
2. **自社のデータを追加** — 補完用のエンドポイントを接続する、スプレッドシートをインポートする、または社内 API から同期します。そのうえで、履歴をスレッド内に表示するか、Customer 360 タブに表示するか、表示しないかを、ワークスペース全体で一度だけ選びます。
3. **全体像を見ながら対応** — チームは履歴を目の前にして回答し、エージェントも同じコンテキストで回答します — 私たちのシステムではなく、自社システムにある情報も含めて。

## 導き出されるから、常に最新のプロフィール

誰かが更新を覚えていなければならないフォームではありません。

### 1人のお客様を、すべてのチャネルで

Messenger のスレッドを開くと、同じ人のサイトチャットと Zalo のメッセージがすでに入っています。共通の電話番号またはメールアドレスで結び付けたものです。似た名前で結び付けることはありません — 共通の識別子がなければ、2つのスレッドは推測でまとめられず、別々のままです。

### 入力していない連絡先情報

会話の途中で顧客が書いた電話番号を検出し、既存の番号と重複を除いたうえで会話に紐付けます — スタッフの番号や引用メッセージの番号は数えずに除外します。

### 自社システムを、パネルの中に

自社で管理するエンドポイントを指定します。こちらは保有している識別子を送り、そちらのシステムは注文、通話、サイト訪問などのタイムライン項目を返します — スレッド内または Customer 360 タブに表示され、キャッシュを有効にしない限り私たちのデータベースにはコピーされません。

### エージェントが使えるコンテキスト

ソースをキャッシュし、外部コンテキストを有効にすると、返信するエージェントはそのキャッシュから読み取ります — 社内 API をメッセージごとの処理経路に置かずに、注文について答えられます。

### 今いるお客様を取り込む

列の対応付けを記憶するスプレッドシートのインポート、またはカーソル方式で HTTP ソースから同期し、毎回前回の続きから再開します。各行は自社の顧客 ID をキーにするため、次のインポートは重複を作らずに更新します。

### API だけでなく、データベースで制御

顧客レコードはワークスペースの権限システムで管理され、データベースのレベルで適用されます。権限のないメンバーは、直接のクエリを含め、どの経路からもその行にアクセスできません。

## Customer 360 に含まれるもの

自動で集まるもの、自社で持ち込むもの、そして誰が見られるか。

### すべての会話の隣に

- 同じ人の他チャネルでのメッセージ
- 検出され、精査された電話番号
- リンク済みの顧客と、その最近の注文
- ラベル、社内メモ、カスタム属性
- 構造化された会話の要約

### 自社システムからの補完

- 自社で管理する HTTP エンドポイント、GET または POST
- 送信する識別子：会話、チャネル、外部 ID、電話番号、メールアドレス、名前、属性
- 表示方法はワークスペースで1つ：インライン、パネル、非表示
- ソースを個人チャットまたはグループチャットに限定
- 認証ヘッダーは保存時に暗号化し、ブラウザには返さない

### 顧客の取り込み

- 列の対応付けを記憶するスプレッドシートのインポート
- 接続モードまたは同期モードの HTTP ソース
- 止まったところから再開するカーソル方式の同期
- 件数とエラー付きの同期履歴
- 外部 ID でアップサートするので、再インポートで更新

### エージェント向け

- 外部コンテキストはソースごとにオプトイン
- キャッシュから提供し、返信のクリティカルパスから外す
- エージェントがお客様について保持するメモリ
- レコードに対して操作できるツール

### チーム向け

- 検索とフィルター付きの顧客一覧
- 顧客ごとの詳細ページ
- 連絡先パネルから、会話を顧客にリンク、または新規作成
- 同じ人の他チャネルを、開いているスレッドの中に

### 管理

- 権限で制御し、データベースで適用
- チャネル単位のアクセスが適用され、開けないチャネルの履歴はそのメンバーのスレッドに表示されない
- 外部データは取得して表示し、黙ってコピーしない
- 補完ソースは削除せずに無効化

## チームがつなぎ合わせなくてよくなること

レコードが自動で組み上がると、手作業での再構築がなくなります。

| 2pm.space がない場合 | 2pm.space を使うと |
| --- | --- |
| 3つのチャネルで連絡してきたお客様が、チームにとっては見知らぬ3人 | 他チャネルのメッセージが、開いたスレッドにすでにある |
| チャットのスレッドから電話番号を手作業でスプレッドシートに書き写す | 番号を自動で検出し、重複を排除して紐づけ |
| 注文履歴は ERP に、会話は受信箱に、そしてどちらも知らないエージェント | 自社システムのデータをスレッド内に表示し、キャッシュ後はエージェントも読める |
| CRM のインポートで、誰も突き合わせない別のリストができる | 自社の顧客 ID をキーにしたインポートで、再インポートは重複ではなく更新になる |
| アカウントを持つ全員が、すべての顧客を閲覧できる | 権限で制御されたレコード。API だけでなくデータベースでも適用 |

## Customer 360 についてのよくある質問

社内システムを接続する前に、チームからよく寄せられる質問です。

### 連絡先リストではなく、360度ビューと言えるのはなぜですか？

手入力ではなく組み立てられたもので、作業する場所にあります：会話を開くと、同じ人の他チャネルでのメッセージ（共通の電話番号またはメールで照合）がすでにスレッド内にあり、そこで検出された番号、リンク済みの顧客とその最近の注文、自社システムからの情報と並んでいます。誰かが更新を覚えていたからではなく、導き出されるから常に最新です。

### 自社の CRM や受注システムのデータを表示できますか？

はい。自社で管理する HTTP エンドポイントを指定します。こちらは保有している識別子（会話、チャネル、外部 ID、電話番号、メールアドレス、名前、カスタム属性）を送り、エンドポイントは認識したタイムライン項目（注文、通話、サイト訪問）を返します。デフォルトでは私たちのデータベースには何もコピーされず、取得して表示するだけです。接続モードの顧客ソースを使えば、会話を開いたときにその人の名前、電話番号、メールアドレスをライブで表示することもできます。

### AI エージェントは返信時にその外部データを使えますか？

そのソースで有効にし、キャッシュを保持している場合に限ります。エージェントは、メッセージごとにエンドポイントへ問い合わせるのではなく、そのキャッシュから外部コンテキストを読み取ります — 遅い、あるいはレート制限のある社内 API が顧客への返信を遅らせることはありません。

### すでにいる顧客をインポートできますか？

はい — 一度設定すれば記憶される列の対応付けでスプレッドシートから、またはカーソル方式で同期する HTTP ソースから取り込めます。各実行は前回の続きから再開します。各行は自社の顧客 ID をキーにするため、再インポートしても同じ顧客が更新され、2件目は作られません。

### 誰が顧客レコードを見られますか？

顧客データはワークスペースの権限システムで制御され、その制御は API だけでなくデータベースでも適用されます — 権限のないメンバーは、どの経路からも行を読めません。さらにチャネル単位のアクセスも適用され、メンバーが開けないチャネルの履歴は、そのメンバーのスレッドには決して表示されません。

### 同じ人が2つのチャネルから連絡してきたらどうなりますか？

もう一方のチャネルのメッセージは、共通の電話番号またはメールで照合され、開いているスレッド内に表示されます。2つの会話自体は別々のままです。似た名前から推測することはありません — 共通の識別子がなければ別々のままです。会話を顧客にリンクすると、照合は番号ではなくそのリンクに従います。2つのチャネルが実は同じアカウントだとわかった場合は、チャネルごと統合できます。
