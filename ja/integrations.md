## ほかのシステムにつながる6つの方法

どんなシステムでも、このどれかですでにカバーできます。

### どんな API も、コードではなく記述で

ツールに URL、メソッド、認証ヘッダー、パラメータの JSON Schema を与え、呼び出すべきエージェントに付与します。すでにあるエンドポイント以外にデプロイするものはありません。

### 記述するより書くほうが早いときはコードで

サンドボックスの Python を、ツールとして呼び出せます。引数は ARGS に届き、print した内容が結果になります。モデルに説明するより書いたほうが早い整形、パース、計算のために。

### MCP に双方向で対応

ツールをあらゆる MCP サーバーに向け、ワンクリックでツールを検出し、ひとつずつオン・オフや承認必須を設定できます — さらに外部の MCP クライアントからこのワークスペースを操作できます。エージェントを作ってくれるコーディングエージェントも含めて。

### エージェントをツールとして

あるエージェントを別のエージェントに公開します。スーパーバイザーは専門エージェントに委任して構造化された回答を受け取れるので、自分のプロンプトの中に専門エージェントの複製を抱える必要はありません。

### チャネルも連携の1つ

Messenger、個人 Zalo、Telegram、Pancake、ウェブサイトウィジェットは、ファーストクラスのチャネルとして接続します。それ以外は、カスタム API チャネル — Webhook の受信と送信 — を通じて届きます。

### イベントをプッシュで受け取る

受信箱のイベントが自社のエンドポイントに届くので、新しいメッセージをきっかけに自社システムで何かを動かせます。配信は記録されるため、受信側が停止していても、失われずに確認できます。

## 開発プロジェクトではなくなること

本来なら自分たちで書いて保守していたはずの連携です。

| 2pm.space がない場合 | 2pm.space を使うと |
| --- | --- |
| コネクタの依頼が誰かのバックログに積まれ、ベンダーの開発待ち | エンドポイントを自分で記述すれば、その日の午後にはエージェントが呼び出せる |
| エージェントが触れる社内サービスごとに、つなぎのコードをデプロイして保守 | Webhook ツールと、必要な部分にはサンドボックスの Python |
| 必要なものに何もアクセスできないので、話すことしかできないエージェント | チャネル、API、データベース、MCP サーバーのすべてを同じループから呼び出せる |
| 専門エージェントのプロンプトを、それを必要とするほかのすべてのエージェントにコピー | 1つのエージェントをツールとして公開し、ほかのエージェントが委任 |
| スクリプトからプラットフォームにアクセスするため、共有設定にトークンを貼り付ける | 作成者の権限の範囲に限定され、1つずつ取り消せるワークスペースの API キー |

## 連携についての質問

社内システムにつなぐ前に、エンジニアからよく寄せられる質問です。

### 一覧にないサービスはどうやって接続しますか？

Webhook ツールを使います。URL、メソッド、認証ヘッダー、パラメータの JSON Schema を設定し、使うべきエージェントに付与します — すべてのエージェントに使わせるならグローバルにします。こちら側にコードをデプロイする必要はなく、そちら側もすでにあるエンドポイント以外は不要です。

### エージェントはコードを実行できますか？

はい — サンドボックス内の Python を、エージェントが呼び出せるツールとして実行できます。記述するより書いたほうが簡単な変換に向いています。ペイロードの整形、モデルに任せるべきでない計算、扱いにくいデータのパースなどです。インターネットへのアクセスは、オンにしない限りオフのままです。

### MCP に対応していますか？

双方向に対応しています。MCP ツールはあらゆるサーバーを指せます。ワンクリックでツールを検出し、エージェントに使わせるもの、承認が必要なものを選びます。さらにプラットフォーム自体も独自の MCP サーバーを公開しているので、外部クライアント — コーディングエージェントも含めて — がワークスペースを操作できます。エージェントの作成、ドキュメントの編集、ボードへのクエリ、スキルやツールの管理などです。

### エージェントが別のエージェントを呼び出せますか？

はい。エージェントをツールとして公開できるので、スーパーバイザーは専門エージェントに委任して構造化された回答を受け取れます。専門エージェントがすでにやっていることを作り直す必要はありません。

### 逆方向の Webhook はどう動きますか？

受信箱のイベントを自社のエンドポイントにプッシュできるので、新しいメッセージや会話の解決をきっかけに、自社システムで何かを動かせます。配信は記録されるため、受信側が停止していた場合も、知らないうちにメッセージを取りこぼすことなく確認できます。

### API はありますか？

はい。API キーはワークスペースごとに発行され、作成したメンバーの権限を引き継ぐため、キーがその人以上のことをすることはできません。同じキーで MCP エンドポイントも認証できます。
