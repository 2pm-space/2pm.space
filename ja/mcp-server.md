## 自社のワークスペースが、 AI クライアントの中に

1つの API キーで、Claude Code、Cursor、あるいはあらゆる MCP クライアントを 2pm.space に接続します。エージェントの構築、ワークフローの修正、ドライブのテーブルへの入力、ボードへのグラフの追加を頼めます — アプリが使うのと同じ操作を通じて、しかもそのキーが許可する範囲だけで実行されます。

[無料で始める](https://2pm.space/signup)

## 3ステップで接続

キー、スニペット、リクエスト。

1. **API キーを作成** — 設定 › API Keys & MCP で、キーを作成し、できることを選びます。キーは、作成した本人以上の権限を持つことはありません。
2. **スニペットを貼り付け** — Claude Code や Cursor 向けのサーバーブロック — エンドポイントと、X-API-Key ヘッダーに入れる自社のキー — をコピーし、クライアントの設定ファイルに貼り付けます。
3. **作業を頼む** — クライアントに、やってほしいことを伝えます。ワークスペースのツールを一覧し、その作業のプレイブックを読み、1つずつ呼び出していきます。

## ワークスペース全体を、ツールとして

読み取り専用の窓ではなく、アプリが行うのと同じ操作です。

### あらゆる MCP クライアント

Streamable HTTP 経由のリモートサーバーなので、Claude Code、Cursor、そのほか MCP を話せるあらゆるクライアントで動きます。アプリ内のセットアップページが、それぞれのスニペットを用意します。

### 300 種類を超えるツール

エージェントとそのキャンバス、ツール、スキル、ナレッジ、ガードレール、メモリ、ドライブのドキュメント・テーブル・マインドマップ・ストーリーボード、データソースとボード、ブランド、コンテンツカレンダー、チャネル。

### キーの範囲に限定

サーバーは、キーの権限が許可するツールだけを一覧表示します。キーは作成したメンバーとして動作するため、読み取り専用の権限だけを与えれば、何も変更できません。

### 長い作業のためのプレイブック

エージェントの構築、RAG のセットアップ、データソースの整備、コンテンツカレンダーの企画など、19本の組み込みガイド — クライアントは始める前にこれを読みます。

### エディタから、自社のドライブへ

ドキュメントの作成と編集、ドライブのテーブルへの入力、マインドマップへのノード追加、ストーリーボードへのショット追加 — その変更は、アプリの中でチームにもそのまま見えます。

### データとボード

接続したデータベースにセマンティックモデル経由でクエリを送り、ボードを作ってグラフを追加し、モデルのメジャーやリレーションシップを調整できます。

## サーバーが公開するもの

接続、キー、そしてクライアントが作業できるワークスペースの範囲。

### 接続

- Streamable HTTP 経由のリモート MCP サーバー
- セットアップページに表示される、1つのエンドポイント
- Claude Code と Cursor 向けのスニペット
- /.well-known/ai-catalog.json で発見可能

### キーと権限

- X-API-Key ヘッダーに入れるワークスペース API キー
- キーは作成したメンバーとして動作
- 権限は作成者の権限を超えない
- 任意の有効期限
- 許可されたツールだけが一覧表示される

### エージェント

- エージェントの作成、設定、削除
- ワークフローキャンバスをノード単位で編集
- ツール、スキル、ナレッジを割り当て
- キャンバスのバージョンを保存・復元
- テストを実行し、トレースを読む

### ドライブとコンテンツ

- ドキュメント、フォルダ、ドライブのテーブル
- マインドマップ — ノード、図形、テーブル
- ストーリーボード — シーン、ショット、フレーム
- ブランドと、その商品・画像
- コンテンツカレンダーのスロット

### データ

- データソース、テーブル、スコープ
- セマンティックモデル：キューブ、メジャー、結合
- CubeQL または SQL でのクエリ
- BI ボード、タブ、グラフ、フィルター

### チャネルと受信箱

- チャネルとその設定
- 会話とそのメッセージ
- ケアエージェントとトリガー
- ガードレールとメモリ

## タブ間のコピー&ペースト vs. MCP

同じ変更を、2通りのやり方で。

| 2pm.space がない場合 | 2pm.space を使うと |
| --- | --- |
| AI にアプリの状況を説明し、その答えを手作業でアプリに貼り戻す。 | クライアントが、ワークスペース自身の操作を通じて直接変更する。 |
| フルアクセスのトークンを、チャットに貼り付けてしまう。 | 作成者ができる範囲に限られたキー — ツール一覧もそこで止まる。 |
| クライアントが、複数ステップのセットアップの仕組みを推測する。 | 先にその作業のプレイブックを読む。 |
| 同じエージェントを、ワークスペースごとに手作業で作り直す。 | 一度頼めば、クライアントがノード単位で組み立てる。 |

## MCP についてのよくある質問

クライアントを接続する前に、みんなが聞くこと。

### どのクライアントが使えますか？

Streamable HTTP 経由のリモート MCP サーバーに対応するクライアントであれば何でも。セットアップページには、Claude Code と Cursor 向けのすぐ使えるスニペットがあります。

### クライアントは自社のワークスペースで何ができますか？

キーが許可する範囲であれば何でも — エージェントの構築とテスト、ドライブのドキュメント・テーブル・マインドマップ・ストーリーボードの編集、接続したデータベースへのクエリ、ボード・ブランド・コンテンツカレンダー・チャネル設定の管理。クライアントに見えるツール一覧は、あらかじめその権限で絞り込まれています。

### AI クライアントにキーを渡しても安全ですか？

キーは作成したメンバーとして動作し、その人が持たない権限を持つことはありません。MCP には承認プロンプトがないため、キーの権限そのものが関門になります — 読み取りだけを行うべきクライアントには読み取り専用の権限を与え、いずれ無効にすべきキーには有効期限を設定してください。

### 自社のクレジットを消費しますか？

ほとんどのツールは単純な読み取りと書き込みです。何かを生成するツール — カレンダーの構成案、画像、エージェントのテスト実行 — は、アプリで行うのとまったく同じようにワークスペースのクレジットを消費します。
