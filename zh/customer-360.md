## 档案如何自动生成

无需专门录入数据。客户档案直接由你正在进行的对话生成。

1. **连接渠道** — 收件箱处理的每段对话都会充实档案：谁发的、从哪里发的、说了什么。无需额外填写——有对话，就有档案。
2. **加入你自己的数据** — 接入一个信息补充端点、导入电子表格，或从内部 API 同步。然后为整个工作区只选一次：历史记录内嵌显示在会话中、显示在 Customer 360 标签页，还是不显示。
3. **掌握全貌再行动** — 团队回复时，历史记录就在眼前；智能体回复时，也用同样的上下文——包括存放在你的系统而非我们系统中的那部分。

## 档案是自动推导出来的，所以永远最新

而不是一张要靠人记得去更新的表单。

### 一个人，所有渠道

打开一个 Messenger 会话，同一个人在网站聊天和 Zalo 的消息已经在里面了，靠共同的手机号或邮箱关联起来。绝不因为名字相似就关联——没有共同标识，两个会话就保持分开，而不是被猜测合并。

### 不用你手动输入的联系方式

客户在对话中写下的手机号会被识别，与已有号码去重，并附加到该会话——员工号码和引用消息里的号码会被剔除，不计入其中。

### 你的系统，就在面板里

指向一个由你掌控的端点。我们发送掌握的标识信息；你的系统返回时间线条目——订单、通话、网站访问——显示在会话中或 Customer 360 标签页里，除非你开启缓存，否则不会复制进我们的数据库。

### 智能体可用的上下文

为数据源开启缓存和外部上下文后，负责回复的智能体会从该缓存读取——无需让你的内部 API 出现在每条消息的关键路径上，也能回答订单问题。

### 带上你现有的客户

从电子表格导入，列映射会被记住；或通过游标从 HTTP 数据源同步，每次运行都从上次停下的地方继续。每一行以你自己的客户 ID 为键，因此下次导入会更新而不是新增重复记录。

### 在数据库层把关，而不只是 API

客户档案受工作区权限系统管控，并在数据库层强制执行，没有权限的成员无论通过什么途径都无法读取这些数据——包括直接查询。

## Customer 360 包含什么

哪些自动生成，哪些由你提供，以及谁有权查看。

### 在每个会话旁边

- 同一个人在其他渠道的消息
- 识别出并整理过的手机号
- 已关联的客户及其近期订单
- 标签、内部备注和自定义属性
- 结构化的会话摘要

### 从你的系统补充信息

- 一个由你掌控的 HTTP 端点，GET 或 POST
- 发送的标识信息：会话、渠道、外部 id、手机号、邮箱、姓名、属性
- 整个工作区一种显示方式：内嵌、面板或隐藏
- 可限定数据源只用于私聊或群聊
- 认证请求头加密存储，绝不返回给浏览器

### 导入客户

- 电子表格导入，记住列映射
- HTTP 数据源，支持连接模式或同步模式
- 基于游标的同步，从停下的地方继续
- 同步历史，含数量和错误
- 按你的外部 id 插入或更新，重复导入会更新已有记录

### 给智能体用

- 外部上下文按数据源选择开启
- 从缓存读取，不在回复的关键路径上
- 智能体保存的关于该客户的记忆
- 可以对档案执行操作的工具

### 给团队用

- 带搜索和筛选的客户列表
- 每位客户一个详情页
- 在联系人面板中把会话关联到客户，或新建客户
- 同一个人的其他渠道，就在你打开的会话里

### 控制

- 权限控制，在数据库层强制执行
- 渠道权限照样生效：成员无权打开的渠道，其历史不会出现在他的会话里
- 外部数据是实时获取的，而不是被悄悄复制
- 信息补充数据源可停用而不必删除

## 关于 Customer 360 的问题

团队在接入内部系统之前常问的问题。

### 它为什么是 360 度视图，而不只是联系人列表？

它是拼合出来的，而不是手动录入的，并且就在你工作的地方：打开一个会话，同一个人在其他渠道的消息——按共同的手机号或邮箱匹配——已经在会话里，旁边是会话中识别出的号码、已关联的客户及其近期订单，以及你自己系统报告的信息。它保持最新，是因为它是推导出来的，而不是靠有人记得去更新。

### 能显示我们自己的 CRM 或订单系统中的数据吗？

可以。你指向一个由你掌控的 HTTP 端点。我们发送掌握的标识信息——会话、渠道、外部 id、手机号、邮箱、姓名、自定义属性——你的端点返回它识别出的时间线条目：订单、通话、网站访问。默认情况下不会复制任何数据到我们的数据库，只是获取并展示。连接模式的客户数据源还能在打开会话时实时显示此人的姓名、手机号和邮箱。

### AI 智能体回复时能用这些外部数据吗？

只有当你为该数据源开启它并保留一份缓存时才可以。智能体从该缓存读取外部上下文，而不是让你的端点在每条消息时都响应——因此缓慢或受限流的内部 API 永远不会拖慢对客户的回复。

### 能导入我们已有的客户吗？

可以——从电子表格导入，列映射设置一次即被记住；或从通过游标同步的 HTTP 数据源导入，每次运行都从上次停下的地方继续。每一行以你自己的客户 ID 为键，因此重新导入会更新同一批客户，而不会再添加一份副本。

### 谁能查看客户档案？

客户数据受工作区权限系统管控，并且在数据库层和 API 层同时强制执行——没有权限的成员无论通过什么途径都读不到这些数据。渠道级访问权限叠加其上：成员无权打开的渠道，其历史永远不会出现在他的会话里。

### 同一个人从两个渠道发消息时会怎样？

另一个渠道的消息会按共同的手机号或邮箱匹配，出现在你打开的会话中，而两个会话本身仍然分开。不会根据相似的名字去猜测——没有共同标识，它们就保持分开。一旦你把会话关联到某个客户，匹配就改为依据该关联而不是号码。如果两个渠道其实是同一个账号，可以把整个渠道合并到另一个渠道。
