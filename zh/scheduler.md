## 让智能体按时上岗

选定智能体，设好时间，查看结果。

1. **选一个智能体和一项任务** — 选择智能体，写下要问它的内容，一行一条消息——每一行都会单独发送并单独作答。
2. **设置运行时间** — 一次性、每天固定时间、每周勾选的那几天、每月的某一天，或一条 cron 表达式——按你选定的时区运行。
3. **查看它做了什么** — 每次运行都会落到该任务的历史记录里，附带每个回答、它的 Token 和成本。可以从列表里立即运行、暂停或取消它。

## 一个知道自己在运行智能体的调度器

不是触发 Webhook 的 cron 任务——而是带着对话、工具和日志的一次运行。

### 五种调度方式

某个日期的一次性运行、每天固定时间、每周勾选的几天、每月的某一天，或任意 cron 表达式。每个调度都按你设置的时区执行，而不是服务器的时区。

### 结果送到该去的地方

智能体带着它的工具一起运行，所以报告写好就能直接发出去：给销售群发一条 Telegram 消息、一封邮件、推送给运营人员，或写进 Drive 表格的一行。

### 能等的任务，成本减半

把一个简单智能体切换到 Batch API，它的运行会走服务商的批处理队列——成本约便宜 50%，24 小时内完成。适用于 Anthropic 和 OpenAI 模型。

### 如果需要，跨运行保留记忆

每次运行都开一个新对话，或不断续写最新那个对话，让智能体记得上一次的内容，也可以发到某个指定对话里。

### 你说停就停

设置有效期或最大运行次数，并选择并发消息数量——从 1 条到 10 条。

### 每次运行都有记录

每次运行都保留状态、开始和结束时间，以及每条消息的回答或报错，附带 Token 和成本——也会汇总在“设置 › 日志”里。

## 关于调度器的问题

人们在自动化第一份报告之前常问的问题。

### 我可以调度什么？

工作区里任何处于启用状态的智能体。你写下它应该收到的消息，一行一条，每次运行都会发送这些消息并记录回答。

### 结果怎么传到我手上？

通过智能体自己的工具。给它配上 Telegram Send Message、Gmail 或 Notify Operators，并在消息里说明结果该发到哪里。每个回答也都会保留在任务的运行历史中。

### Batch API 模式是什么？

它把一次运行的消息交给模型提供商的批处理队列，而不是立即作答。成本约为一半，24 小时内完成。它适用于运行在 Anthropic 或 OpenAI 模型上的简单智能体；Agentic 工作流需要多轮执行，所以始终立即运行。

### 它用的是哪个时区？

你在任务上选定的那个——默认是你浏览器所在的时区。每天、每周和每月的时间都按这个时区来读取。

### 可以调度一个带 Human Review 步骤的智能体吗？

不可以。一次调度运行没有人来批准它，所以对话框不会调度一个工作流中包含 Human Review 节点的智能体。

### 任务可以在运行若干次后自动停止吗？

可以。设置最大运行次数、有效期，或两者都设。你也可以随时暂停、恢复或取消一个任务。
