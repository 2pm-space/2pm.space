## 4개 채널, 하나의 대기열

고객이 이미 메시지를 보내고 있는 곳 — 채널마다 다른 채널에 없는 고유한 기능이 있습니다.

### Messenger

*다이렉트 메시지와 페이지 댓글*

- 연결한 모든 페이지를 하나의 대기열에서
- 게시물 댓글에 공개 답글 또는 비공개 답장으로 응답
- 광고 유입 정보와 상품 카드를 대화 스레드에 표시
- 페이지를 추가하면 기존 대화 기록까지 불러오기

### Telegram

*내 봇, 1:1 채팅과 그룹*

- 내 봇에 직접 고른 에이전트가 답변
- 그룹 채팅에서도 멤버 한 명 한 명을 각각의 화자로 구분
- 사진, 파일, 음성 메시지 — 음성은 텍스트로 변환

### 웹사이트 위젯

*내 사이트에 설치하는 위젯*

- 스크립트 태그 하나, 허용한 도메인에서만 작동
- 원하는 색상, 인사말, 런처, 빠른 답변
- 사전 채팅 양식, 8개 언어, 기기별 위치 설정

### 개인 Zalo

*QR 코드로 연결하는 내 계정*

- QR 코드로 로그인 — Official Account 없이 사용
- 1:1 채팅과 그룹 채팅을 같은 대기열에서
- 대화 스레드에서 바로 전화번호로 친구 요청

추가 연결: Pancake · 사용자 지정 API — 웹훅 수신, 웹훅 발신 · Zalo Official Account (출시 예정)

## 첫 메시지부터 감사 인사까지

고객이 어느 채널에서든 메시지를 보냅니다. 에이전트가 상담하고, 주문을 받고, 배송을 접수하고, 감사 인사를 전합니다 — 대화의 방향이 바뀌어도 어디로 가야 할지 압니다.

**고객 문의 채널**

- **Messenger:** *파란색 아직 재고 있나요?*
- **Telegram:** *다낭까지 배송되나요?*
- **웹사이트 위젯:** *이거 두 개면 얼마예요?*
- **개인 Zalo:** *물건 받고 결제해도 되나요?*

### 2pm AI가 상담합니다

모든 채널 뒤에서 하나의 에이전트가 워크스페이스에 담긴 모든 지식을 바탕으로 응대합니다.

- **지식** — 문서와 카탈로그를 바탕으로 답변하며, 상품 사진도 포함합니다
- **스킬** — 영업 플레이북 — 무엇을 묻고, 무엇을 제안하고, 어떤 말투로 말할지
- **도구** — 대화 중에 상품, 지난 주문, 배송비를 조회합니다
- **메모리** — 고객이 지난번에 한 말을 기억합니다
- **Customer 360** — 고객이 이용한 모든 채널을 하나의 기록으로
- **가드레일** — 모든 답변이 말하고 행동해도 되는 범위를 벗어나지 않게 합니다

1. **처리** — 주문 품목, 전화번호, 배송 주소를 고객에게 다시 확인합니다. `주소 저장됨`
2. **주문 생성** — 카탈로그 가격으로 판매 주문을 만듭니다 — 팀이 확인할 초안으로 두거나 바로 제출합니다. `SO-2026-48213`
3. **COD 배송 접수** — 수령 시 받을 금액과 함께 Viettel Post에 접수하거나, 자체 택배사를 쓴다면 배송 전표로 남겨 둡니다. `COD · 운송장 번호`
4. **감사 인사** — 배송 완료가 보고되면 이벤트 규칙이 감사 메시지를 보냅니다 — 대화 내용을 바탕으로 쓰거나 템플릿을 사용합니다. `배송 완료 → 감사 발송`

**진행 중에**

- **전화번호를 알려 주면 → Zalo 친구 추가.** 번호가 연락처에 고정되고, 개인 Zalo가 친구 요청을 보냅니다 — 오전 8시부터 오후 8시 사이에 간격을 두고 보냅니다. 요청을 수락하면 Zalo 채팅이 같은 고객 기록에 합쳐집니다. `+84 ••• 412 → Zalo`
- **연락이 끊기면 → 케어가 후속 연락합니다.** 케어 에이전트가 대화를 읽고, 설정한 무응답 시간이 지나면 후속 메시지를 보냅니다 — 방해 금지 시간을 지키고, 1인당 횟수를 제한하며, 채널의 메시지 발송 가능 기간 안에서만 보냅니다. `2시간 무응답 → 후속 연락`
- **상담원을 찾으면 → 팀이 개입합니다.** 에이전트가 대화를 바로 여는 푸시 알림을 팀에 보냅니다. 누구든 거기서 답하거나, AI를 중지해 대화를 직접 맡을 수 있습니다. `알림 → AI 중지`
- **스팸이나 욕설을 보내면 → 에이전트가 답변을 멈춥니다.** 해당 대화의 AI와 케어를 끄고, 팀에 한 줄 사유를 남깁니다. 누구든 받은편지함에서 다시 켤 수 있습니다. `AI 끔 · 사유 기록`

## 페이지 연결부터 일하는 에이전트까지

세 단계면 충분하고, 첫 대화는 당일에 응답됩니다.

1. **채널 연결** — Facebook 페이지, Zalo 계정, Telegram 봇 또는 웹사이트 위젯을 연결하세요. 기존 대화 기록을 불러오므로, 받은편지함은 빈 목록이 아니라 이미 있던 대화와 함께 열립니다.
2. **에이전트 배치** — 어떤 에이전트가 어떤 채널에서 답할지 고르고 필요한 문서와 도구를 주세요. 고객이 연달아 보낸 메시지가 끝나면 에이전트가 스스로 답합니다 — 얼마나 기다릴지, 어떤 태그의 대화를 팀에 맡길지, 테스트하는 동안 답변을 앱 안에만 두는 샌드박스 모드를 정할 수 있습니다.
3. **지켜보고, 개입하고, 개선** — 모든 답변은 실행 기록(도구 호출과 비용)을 실행 로그에 남깁니다. 사람이 필요한 대화에서는 AI를 중지하고, 답변을 평가하거나 개선하세요. 수정 내용은 에이전트에 바로 반영되고 나중에 학습에도 쓰입니다.

## 받은편지함을 실제로 운영하는 팀을 위해

페이지에 덧붙인 챗봇이 아니라, 팀과 에이전트가 함께 일하는 공유 대기열입니다.

### 최전선에 선 에이전트

에이전트 하나를 채널에 지정하면 상품 카탈로그, 문서, 그 고객에 대해 기억하는 모든 것을 활용해 우리 브랜드의 말투로 답합니다. 도구도 쓸 수 있어서, 모른다고 사과하는 대신 주문을 직접 조회합니다.

### 매끄러운 상담원 인계

팀원 누구나 대화 도중에 답할 수 있습니다 — 같은 대화, 같은 기록 그대로. 팀원의 답변은 에이전트가 쓰던 답을 취소하지만 에이전트를 끄지는 않습니다. AI 중지를 누르면 누군가 다시 켤 때까지 대화가 팀에 넘어갑니다. 사람이 결정해야 할 일은 사람에게 맡깁니다. 에이전트가 받은 주문은 팀이 확정할 때까지 임시 상태로 기다리고(자동 확정을 허용한 경우 제외), 대화를 바로 여는 푸시 알림을 팀에 보낼 수도 있습니다.

### 대화 다섯 개가 아닌, 고객 한 명

채널 간 연락처를 매칭하므로 Facebook 댓글, Messenger 답장, Zalo 메시지가 하나의 이력을 가진 한 사람으로 묶입니다 — 전화번호, 태그, 속성까지 함께.

### 놓치지 않고 남기는 전화번호

고객이 대화 중에 입력한 번호를 감지하고, 이미 보유한 번호와 중복을 제거한 뒤 연락처에 고정합니다 — 직원 번호나 전달된 인용문 속 번호 같은 잡음은 세지 않고 걸러 냅니다.

### 대화를 읽고 보내는 케어 후속 연락

대화가 끊기면 이력을 읽은 에이전트가 후속 연락을 합니다 — 설정한 방해 금지 시간을 지키고, 한 사람에게 연락하는 횟수를 제한하며, 똑같은 메시지를 일괄 발송하는 일은 없습니다.

### 바로 행동으로 옮길 수 있는 숫자

대화량, 응답 시간, 채널별 분석을 시간 단위로 미리 계산해 둡니다. 누군가 기간을 바꿀 때마다 1년 치 메시지를 훑는 대신 대시보드가 즉시 열립니다.

## AI Inbox에 관한 질문

첫 페이지를 에이전트에 맡기기 전에 팀들이 묻는 것들입니다.

### 어떤 메시징 채널을 연결할 수 있나요?

Facebook Messenger(페이지 게시물 댓글 포함), Telegram, QR 코드로 로그인하는 개인 Zalo, Pancake, 그리고 내 웹사이트에 삽입하는 채팅 위젯을 연결할 수 있으며, Zalo Official Account는 출시 예정입니다. 그 밖의 채널은 사용자 지정 API 채널로 연결합니다. 일반 웹훅으로 받고 일반 웹훅으로 보내는 방식이라, 저희 쪽에서 새로 코드를 작성할 필요가 없습니다.

### AI가 알아서 답하나요, 아니면 직원이 계속 답해야 하나요?

둘 다입니다. 고객이 연달아 보낸 메시지가 끝나면 에이전트가 새 메시지마다 스스로 답하고, 팀은 언제든 같은 대화에서 답할 수 있습니다. 팀원의 답변은 에이전트가 쓰던 답을 취소하고, AI는 켜진 채로 남습니다. AI 중지를 누르면 누군가 다시 켤 때까지 대화가 팀에 넘어가며(그 대화의 케어 후속 연락도 멈춥니다), 선택한 태그가 붙은 대화는 처음부터 팀에 맡길 수 있습니다. 대화 도중 승인 단계는 없습니다. 주문은 주문 자체가 확인 지점입니다 — 에이전트가 임시 주문을 만들고 팀이 확정합니다(자동 확정을 허용한 경우 제외).

### 같은 고객의 대화가 한데 묶이나요?

네. 대화는 공통된 전화번호나 이메일로 연결되므로, Facebook 게시물에 댓글을 달고 나중에 Zalo로 메시지를 보낸 사람도 하나의 이력을 가진 한 명의 고객으로 표시됩니다 — 대화에서 감지한 전화번호, 팀이 입력한 사용자 지정 속성, 자체 시스템에서 가져온 프로필 데이터까지 포함됩니다.

### 이미지, 음성 메시지, 파일은 어떻게 되나요?

대화와 함께 저장되고 대화 안에 바로 표시됩니다 — 사진, 앨범, 스티커, 파일, 위치, 투표, 상품 카드가 깨진 링크가 아니라 원래 모습 그대로 보입니다. 음성 메시지는 자동으로 텍스트로 변환되므로, 에이전트가 실제로 읽고 답할 수 있는 검색 가능한 텍스트가 됩니다.

### 어떤 직원이 어떤 채널을 볼지 제어할 수 있나요?

네. 채널 접근 권한은 멤버별, 역할별, 팀별로 부여하므로, 대행사라면 고객사 담당 팀에게 페이지 하나만 열어 주고 나머지 워크스페이스는 보이지 않게 할 수 있습니다. 워크스페이스의 다른 모든 기능도 같은 권한 체계를 사용합니다.

### 연락이 끊긴 고객에게 후속 연락을 할 수 있나요?

네 — 그것이 바로 케어의 역할입니다. 트리거(N시간 동안 대화 없음, 태그, 필터), 절대 발송하지 않을 방해 금지 시간, 한 사람에게 연락할 수 있는 횟수 상한을 설정합니다. 후속 메시지 자체는 고정된 템플릿의 일괄 발송이 아니라, 에이전트가 대화 이력을 바탕으로 작성합니다.
