# Customer 360 — 모든 채널을 아우르는 하나의 기록

> 받은편지함 안의 Customer 360: 대화를 열면 같은 사람이 다른 채널에서 보낸 메시지가 이미 들어와 있습니다 — 전화번호나 이메일로 매칭되어, 감지된 번호, 연결된 고객, 자체 시스템의 실시간 데이터와 함께 표시됩니다.

*모든 채널, 하나의 기록*

## Customer 360, 이미 일어난 일로 완성됩니다

모든 채널의 대화, 대화 중에 포착한 전화번호, 자체 시스템의 실시간 데이터가 하나의 고객 뷰로 모입니다 — 팀이 읽고, 에이전트가 답변의 근거로 삼는 바로 그 뷰입니다.

## 기록이 스스로 만들어지는 방식

데이터 입력 프로젝트는 필요 없습니다. 프로필은 이미 나누고 있는 대화에서 만들어집니다.

1. **채널 연결** — 받은편지함이 처리하는 모든 대화가 기록을 만듭니다. 누가, 어디서, 무엇에 대해 썼는지. 따로 입력할 것은 없습니다 — 대화가 있으니 프로필도 있습니다.
2. **자체 데이터 추가** — 보강 엔드포인트를 연결하거나, 스프레드시트를 가져오거나, 내부 API에서 동기화하세요. 그런 다음 기록을 대화 안에 표시할지, Customer 360 탭에 표시할지, 표시하지 않을지를 워크스페이스 전체에 대해 한 번만 고르면 됩니다.
3. **전체 그림을 보고 일하기** — 팀은 이력을 눈앞에 두고 답하고, 에이전트도 같은 맥락으로 답합니다 — 저희가 아닌 여러분의 시스템에 있는 정보까지 포함해서요.

## 자동으로 만들어지기에 늘 최신인 프로필

누군가 업데이트를 잊지 말아야 하는 양식이 아닙니다.

### 한 사람, 모든 채널

Messenger 대화를 열면 같은 사람의 웹사이트 채팅과 Zalo 메시지가 이미 들어와 있습니다. 공유하는 전화번호나 이메일로 연결된 것입니다. 비슷해 보이는 이름으로는 절대 연결하지 않습니다 — 공통 식별자가 없으면 두 대화는 추측으로 합쳐지지 않고 따로 유지됩니다.

### 직접 입력하지 않은 연락처 정보

고객이 대화 중에 쓴 전화번호를 감지하고, 이미 가진 번호와 중복을 제거해 대화에 연결합니다 — 직원 번호와 인용된 메시지 속 번호는 세지 않고 걸러 냅니다.

### 패널 안의 자체 시스템

직접 관리하는 엔드포인트를 지정하세요. 저희는 보유한 식별자를 보내고, 귀사 시스템은 주문, 통화, 웹 방문 같은 타임라인 항목으로 응답합니다 — 대화 안이나 Customer 360 탭에 표시되며, 캐시를 켜지 않는 한 저희 데이터베이스에 복사되지 않습니다.

### 에이전트가 쓸 수 있는 맥락

소스를 캐시하고 외부 컨텍스트를 켜면, 답장하는 에이전트가 그 캐시에서 읽습니다 — 내부 API가 메시지마다 처리 경로에 놓이지 않아도 주문에 대해 답할 수 있습니다.

### 보유한 고객 데이터 가져오기

열 매핑을 기억하는 스프레드시트 가져오기, 또는 커서 방식으로 HTTP 소스에서 동기화해 매번 지난번에 멈춘 곳부터 이어 갑니다. 각 행은 귀사의 고객 ID를 키로 삼기 때문에, 다음 가져오기는 중복을 만들지 않고 업데이트합니다.

### API뿐 아니라 데이터베이스에서도 통제

고객 기록은 워크스페이스 권한 체계로 관리되고 데이터베이스 수준에서 강제되므로, 권한이 없는 멤버는 직접 쿼리를 포함해 어떤 경로로도 해당 행에 접근할 수 없습니다.

## Customer 360에 담기는 것

저절로 들어오는 것, 직접 가져오는 것, 그리고 볼 수 있는 사람.

### 모든 대화 옆에

- 같은 사람이 다른 채널에서 보낸 메시지
- 감지되고 정리된 전화번호
- 연결된 고객과 최근 주문
- 라벨, 내부 메모, 사용자 정의 속성
- 구조화된 대화 요약

### 자체 시스템의 데이터 보강

- 직접 관리하는 HTTP 엔드포인트, GET 또는 POST
- 전송하는 식별자: 대화, 채널, 외부 ID, 전화번호, 이메일, 이름, 속성
- 워크스페이스 단위의 표시 방식 하나: 인라인, 패널 또는 숨김
- 소스를 1:1 대화 또는 그룹 대화로 제한
- 저장 시 암호화되고 브라우저로 절대 반환되지 않는 인증 헤더

### 고객 데이터 들여오기

- 열 매핑을 기억하는 스프레드시트 가져오기
- 연결 모드 또는 동기화 모드의 HTTP 소스
- 멈춘 곳부터 이어 가는 커서 기반 동기화
- 건수와 오류가 담긴 동기화 기록
- 외부 ID 기준 업서트로, 다시 가져오면 업데이트

### 에이전트용

- 소스별로 켜는 외부 컨텍스트
- 캐시에서 제공되어 답변의 핵심 경로에서 분리
- 에이전트가 고객에 대해 간직하는 메모리
- 기록에 작업을 수행할 수 있는 도구

### 팀용

- 검색과 필터를 지원하는 고객 목록
- 고객별 상세 페이지
- 연락처 패널에서 대화를 고객에 연결하거나 새로 만들기
- 같은 사람의 다른 채널을, 열어 둔 대화 안에서 바로

### 제어

- 데이터베이스에서 강제되는 권한 제어
- 채널 접근 권한 적용: 팀원이 열 수 없는 채널의 기록은 그 팀원의 대화에 나타나지 않음
- 외부 데이터는 조용히 복사하지 않고 조회만
- 삭제하지 않고 비활성화할 수 있는 보강 소스

## Customer 360에 관한 질문

사내 시스템을 연결하기 전에 팀들이 묻는 것들입니다.

### 연락처 목록이 아니라 360 뷰라고 부르는 이유는 무엇인가요?

직접 입력하는 것이 아니라 조립되며, 일하는 곳에 있습니다: 대화를 열면 같은 사람이 다른 채널에서 보낸 메시지가 — 공유하는 전화번호나 이메일로 매칭되어 — 이미 대화 안에 있고, 그 대화에서 감지된 번호, 연결된 고객과 최근 주문, 자체 시스템이 알려 주는 정보가 함께 표시됩니다. 누군가 업데이트를 기억해서가 아니라, 도출되기 때문에 항상 최신입니다.

### 자체 CRM이나 주문 시스템의 데이터도 보여 줄 수 있나요?

네. 직접 관리하는 HTTP 엔드포인트를 지정하면 됩니다. 저희는 보유한 식별자 — 대화, 채널, 외부 ID, 전화번호, 이메일, 이름, 사용자 정의 속성 — 를 보내고, 엔드포인트는 인식한 타임라인 항목, 즉 주문, 통화, 웹 방문으로 응답합니다. 기본적으로 저희 데이터베이스에는 아무것도 복사되지 않으며, 조회해서 표시만 합니다. 연결 모드의 고객 소스를 쓰면 대화를 열 때 그 사람의 이름, 전화번호, 이메일을 실시간으로 보여 줄 수도 있습니다.

### AI 에이전트가 답할 때 그 외부 데이터를 쓸 수 있나요?

해당 소스에서 켜고 캐시 사본을 유지할 때만 가능합니다. 에이전트는 메시지마다 엔드포인트에 응답을 요구하는 대신 그 캐시에서 외부 컨텍스트를 읽습니다 — 느리거나 요청 제한이 있는 내부 API가 고객 답장을 늦추는 일은 없습니다.

### 이미 보유한 고객을 가져올 수 있나요?

네 — 한 번 설정하면 기억되는 열 매핑으로 스프레드시트에서, 또는 커서 방식으로 동기화되는 HTTP 소스에서 가져올 수 있어 매번 지난번에 멈춘 곳부터 이어 갑니다. 각 행은 귀사의 고객 ID를 키로 삼기 때문에, 다시 가져오면 같은 고객이 업데이트되고 두 번째 사본이 생기지 않습니다.

### 누가 고객 기록을 볼 수 있나요?

고객 데이터는 워크스페이스 권한 시스템으로 제어되며, 이 제어는 API뿐 아니라 데이터베이스에서도 강제됩니다 — 권한이 없는 멤버는 어떤 경로로도 데이터를 읽을 수 없습니다. 채널 접근 권한도 함께 적용되어, 팀원이 열 수 없는 채널의 기록은 그 팀원의 대화에 절대 나타나지 않습니다.

### 같은 사람이 두 채널에서 메시지를 보내면 어떻게 되나요?

다른 채널의 메시지는 공유하는 전화번호나 이메일로 매칭되어 열어 둔 대화 안에 나타나고, 두 대화 자체는 따로 유지됩니다. 비슷한 이름으로 추측하지 않습니다 — 공통 식별자가 없으면 따로 남습니다. 대화를 고객에 연결하면 매칭은 번호 대신 그 연결을 따릅니다. 두 채널이 사실 같은 계정으로 밝혀지면 채널 전체를 다른 채널로 병합할 수 있습니다.
