## 이미 쓰고 있는 모든 시스템과 연결하세요

메시징 채널, HTTP API, 데이터베이스, MCP 서버, 샌드박스 코드 — 코드가 아니라 설명으로 연결하므로, 에이전트는 모른다고 사과하는 대신 답을 가진 시스템에 직접 접근합니다.

## 나머지 스택에 닿는 여섯 가지 방법

어떤 시스템이든, 이 중 하나로 이미 연결됩니다.

### 코드 대신 설명으로 연결하는 모든 API

도구에 URL, 메서드, 인증 헤더, 파라미터용 JSON Schema를 지정한 뒤 호출해야 할 에이전트에 허용하세요. 이미 가진 엔드포인트 외에 배포할 것은 없습니다.

### 설명보다 코드가 쉬울 때

샌드박스의 Python을 도구로 호출합니다. 인수는 ARGS로 들어오고, print한 내용이 결과가 됩니다. 모델에 설명하기보다 직접 쓰는 편이 빠른 변환, 파싱, 계산을 위해.

### 양방향 MCP

도구를 어떤 MCP 서버에든 연결하고, 클릭 한 번으로 도구를 검색해 하나씩 켜거나 끄거나 승인 필수로 두세요 — 그리고 외부 MCP 클라이언트에서 이 워크스페이스를 조작하세요. 에이전트를 대신 만들어 주는 코딩 에이전트도 포함됩니다.

### 도구가 되는 에이전트

한 에이전트를 다른 에이전트에 노출하세요. 감독 에이전트가 전문 에이전트에게 위임하고 구조화된 답을 돌려받습니다 — 자기 프롬프트 안에 전문 에이전트를 하나 더 복사해 두는 대신에요.

### 연동으로서의 채널

Messenger, 개인 Zalo, Telegram, Pancake, 웹사이트 위젯이 정식 채널로 연결됩니다. 그 밖의 것은 사용자 지정 API 채널 — 웹훅 인, 웹훅 아웃 — 으로 들어옵니다.

### 나에게 전달되는 이벤트

받은편지함 이벤트가 직접 관리하는 엔드포인트로 전달되므로, 새 메시지가 스택의 무언가를 트리거할 수 있습니다. 전송이 기록되므로, 수신 측이 다운되었을 때도 사라지지 않고 드러납니다.

## 연동에 관한 질문

사내 시스템에 연결하기 전에 엔지니어들이 묻는 것들입니다.

### 목록에 없는 서비스는 어떻게 연결하나요?

웹훅 도구로 연결합니다. URL, 메서드, 인증 헤더, 파라미터용 JSON Schema를 지정하고 사용할 에이전트에 허용하세요 — 모든 에이전트가 쓰게 하려면 전역으로 설정합니다. 저희 쪽에 코드를 배포할 필요가 없고, 여러분 쪽도 이미 가진 엔드포인트 외에는 필요 없습니다.

### 에이전트가 코드를 실행할 수 있나요?

네 — 샌드박스의 Python을 에이전트가 호출할 수 있는 도구로 실행합니다. 설명하기보다 직접 쓰는 편이 쉬운 변환에 알맞습니다. 페이로드 재구성, 모델에 맡기면 안 되는 계산, 까다로운 데이터 파싱 같은 것들입니다. 인터넷 접근은 직접 켜기 전까지 꺼져 있습니다.

### MCP를 지원하나요?

양방향 모두 지원합니다. MCP 도구는 어떤 서버든 가리킬 수 있습니다. 클릭 한 번으로 도구를 검색한 뒤, 에이전트가 쓸 도구와 승인이 필요한 도구를 고르세요. 또한 플랫폼이 자체 MCP 서버를 공개하므로 외부 클라이언트 — 코딩 에이전트 포함 — 가 워크스페이스를 조작할 수 있습니다. 에이전트 생성, 문서 편집, 보드 조회, 스킬과 도구 관리까지.

### 에이전트가 다른 에이전트를 호출할 수 있나요?

네. 에이전트를 도구로 노출할 수 있으므로, 감독 에이전트가 전문 에이전트에게 위임하고 구조화된 답을 돌려받을 수 있습니다. 전문 에이전트가 이미 하는 일을 다시 구현할 필요가 없습니다.

### 반대 방향의 웹훅은 어떻게 작동하나요?

받은편지함 이벤트를 직접 관리하는 엔드포인트로 보낼 수 있으므로, 새 메시지나 해결된 대화가 자체 스택의 무언가를 트리거할 수 있습니다. 전송이 기록되므로, 수신 측이 다운되었던 경우에도 모르고 지나치는 메시지 없이 바로 드러납니다.

### API가 있나요?

네. API 키는 워크스페이스별로 발급되며 키를 만든 멤버의 권한을 그대로 가지므로, 키가 그 사람보다 더 많은 일을 할 수는 없습니다. 같은 키로 MCP 엔드포인트도 인증합니다.

엔드포인트를 설명하거나, 데이터베이스를 연결하거나, MCP 서버를 지정하세요. 무료로 시작하며, 신용카드는 필요 없습니다.
