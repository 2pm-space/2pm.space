# Customer 360 — ข้อมูลลูกค้าชุดเดียว ครอบคลุมทุกช่องทาง

> Customer 360 ในกล่องข้อความ: เปิดบทสนทนาแล้วข้อความของคนเดียวกันจากช่องทางอื่นก็อยู่ในนั้นแล้ว — จับคู่ด้วยเบอร์โทรหรืออีเมล — ข้างเบอร์ที่ตรวจพบ ลูกค้าที่เชื่อมไว้ และข้อมูลสดจากระบบของคุณเอง

## Customer 360 ที่ประกอบขึ้น จากสิ่งที่เกิดขึ้นจริง

บทสนทนาจากทุกช่องทาง เบอร์โทรที่จับได้ระหว่างแชท และข้อมูลสดจากระบบของคุณเอง รวมกันเป็นมุมมองลูกค้าหนึ่งเดียว — ที่ทีมของคุณอ่าน และเอเจนต์ใช้ตอบ

## ข้อมูลลูกค้าสร้างตัวเองอย่างไร

ไม่ต้องมีโปรเจกต์กรอกข้อมูล โปรไฟล์สร้างจากบทสนทนาที่คุณมีอยู่แล้ว

1. **เชื่อมช่องทางของคุณ** — ทุกบทสนทนาที่กล่องข้อความดูแลช่วยสร้างข้อมูล: ใครทักมา จากที่ไหน เรื่องอะไร ไม่ต้องกรอกอะไรเพิ่ม — โปรไฟล์มีอยู่เพราะบทสนทนามีอยู่
2. **เพิ่มข้อมูลของคุณเอง** — เชื่อม endpoint เติมข้อมูล นำเข้าสเปรดชีต หรือซิงก์จาก API ภายใน จากนั้นเลือกครั้งเดียวสำหรับทั้ง workspace ว่าจะแสดงประวัติในบทสนทนา ในแท็บ Customer 360 หรือไม่แสดงเลย
3. **ทำงานจากภาพรวมทั้งหมด** — ทีมของคุณตอบโดยมีประวัติอยู่ตรงหน้า และเอเจนต์ก็ตอบด้วยบริบทเดียวกัน — รวมถึงส่วนที่อยู่ในระบบของคุณ ไม่ใช่ของเรา

## โปรไฟล์ที่เป็นปัจจุบัน เพราะสร้างจากข้อมูลจริง

ไม่ใช่ฟอร์มที่ต้องมีคนคอยจำมาอัปเดต

### คนเดียว ทุกช่องทาง

เปิดบทสนทนา Messenger แล้วข้อความจากแชทเว็บไซต์และ Zalo ของคนเดียวกันก็อยู่ในนั้นแล้ว เชื่อมกันด้วยเบอร์โทรหรืออีเมลที่ใช้ร่วมกัน ไม่มีอะไรถูกเชื่อมเพียงเพราะชื่อคล้ายกัน — ถ้าไม่มีตัวระบุร่วม สองบทสนทนาจะแยกกัน ไม่ถูกเดารวมเข้าด้วยกัน

### ข้อมูลติดต่อที่คุณไม่ต้องพิมพ์

เบอร์โทรที่ลูกค้าพิมพ์ระหว่างแชทจะถูกตรวจพบ ตัดตัวซ้ำกับเบอร์ที่คุณมีอยู่แล้ว และผูกไว้กับบทสนทนา — เบอร์ของพนักงานและเบอร์ในข้อความที่อ้างอิงจะถูกคัดออก ไม่ถูกนับรวม

### ระบบของคุณ ในแผงข้าง

ชี้ไปที่ endpoint ที่คุณควบคุม เราส่งตัวระบุที่เรามี ระบบของคุณตอบกลับเป็นรายการไทม์ไลน์ — ออร์เดอร์ การโทร การเข้าชมเว็บ — แสดงในบทสนทนาหรือในแท็บ Customer 360 และไม่ถูกคัดลอกเข้าฐานข้อมูลของเรา เว้นแต่คุณเปิดการแคช

### บริบทที่เอเจนต์ใช้ได้

แคชแหล่งข้อมูลและเปิดบริบทภายนอก แล้วเอเจนต์ที่ตอบจะอ่านจากแคชนั้น — จึงตอบเรื่องออร์เดอร์ได้โดยไม่ต้องให้ API ภายในของคุณอยู่ในเส้นทางของทุกข้อความ

### นำลูกค้าที่มีอยู่เข้ามา

นำเข้าจากสเปรดชีตด้วยการจับคู่คอลัมน์ที่ระบบจำไว้ หรือซิงก์จากแหล่ง HTTP แบบ cursor เพื่อให้แต่ละรอบทำต่อจากจุดที่รอบก่อนหยุด แต่ละแถวอิงรหัสลูกค้าของคุณเอง การนำเข้าครั้งถัดไปจึงอัปเดตแทนที่จะเพิ่มข้อมูลซ้ำ

### คุมสิทธิ์ที่ฐานข้อมูล ไม่ใช่แค่ที่ API

ข้อมูลลูกค้าอยู่ภายใต้ระบบสิทธิ์ของเวิร์กสเปซ และบังคับใช้ที่ระดับฐานข้อมูล สมาชิกที่ไม่มีสิทธิ์จึงเข้าถึงแถวข้อมูลไม่ได้ทุกเส้นทาง — รวมถึงการคิวรีตรง

## Customer 360 มีอะไรบ้าง

อะไรมาเอง อะไรที่คุณนำเข้า และใครมีสิทธิ์เห็น

### ข้างทุกบทสนทนา

- ข้อความของคนเดียวกันจากช่องทางอื่น
- เบอร์โทรที่ตรวจพบ ผ่านการคัดกรองแล้ว
- ลูกค้าที่เชื่อมไว้ พร้อมออร์เดอร์ล่าสุด
- ป้ายกำกับ โน้ตภายใน และแอตทริบิวต์ที่กำหนดเอง
- สรุปบทสนทนาแบบมีโครงสร้าง

### เติมข้อมูลจากระบบของคุณ

- HTTP endpoint ที่คุณควบคุม แบบ GET หรือ POST
- ตัวระบุที่ส่ง: บทสนทนา ช่องทาง external id เบอร์โทร อีเมล ชื่อ แอตทริบิวต์
- ตัวเลือกการแสดงผลเดียวสำหรับทั้ง workspace: ในบรรทัด แผง หรือซ่อน
- จำกัดแหล่งข้อมูลเฉพาะแชทส่วนตัวหรือแชทกลุ่ม
- Auth header เข้ารหัสขณะจัดเก็บ ไม่ถูกส่งกลับไปที่เบราว์เซอร์

### นำลูกค้าเข้าระบบ

- นำเข้าจากสเปรดชีต พร้อมจำการจับคู่คอลัมน์
- แหล่ง HTTP แบบ connect หรือ sync
- ซิงก์แบบ cursor ที่ทำต่อจากจุดที่หยุด
- ประวัติการซิงก์พร้อมจำนวนและข้อผิดพลาด
- Upsert ตาม external id ของคุณ นำเข้าซ้ำจึงเป็นการอัปเดต

### สำหรับเอเจนต์

- เลือกเปิดบริบทภายนอกได้ทีละแหล่ง
- ดึงจากแคช ไม่อยู่บนเส้นทางหลักของการตอบ
- หน่วยความจำที่เอเจนต์เก็บไว้เกี่ยวกับลูกค้า
- เครื่องมือที่ดำเนินการกับข้อมูลลูกค้าได้

### สำหรับทีมของคุณ

- รายชื่อลูกค้าพร้อมการค้นหาและตัวกรอง
- หน้ารายละเอียดของลูกค้าแต่ละคน
- เชื่อมบทสนทนากับลูกค้า หรือสร้างใหม่ จากแผงข้อมูลผู้ติดต่อ
- ช่องทางอื่นของคนเดียวกัน อยู่ในบทสนทนาที่คุณเปิด

### การควบคุม

- คุมสิทธิ์ และบังคับใช้ที่ฐานข้อมูล
- สิทธิ์ระดับช่องทางยังมีผล: ประวัติจากช่องทางที่พนักงานเปิดไม่ได้จะไม่ปรากฏในบทสนทนาของเขา
- ข้อมูลภายนอกดึงมาแสดง ไม่ถูกคัดลอกเก็บเงียบๆ
- ปิดแหล่งเติมข้อมูลได้โดยไม่ต้องลบ

## คำถามเกี่ยวกับ Customer 360

สิ่งที่ทีมต่างๆ ถามก่อนเชื่อมระบบภายในเข้ามา

### อะไรทำให้เป็นมุมมอง 360 ไม่ใช่แค่รายชื่อผู้ติดต่อ?

มันถูกประกอบขึ้น ไม่ได้พิมพ์ใส่เอง และอยู่ตรงที่คุณทำงาน: เปิดบทสนทนาแล้วข้อความของคนเดียวกันจากช่องทางอื่น — จับคู่ด้วยเบอร์โทรหรืออีเมลที่ใช้ร่วมกัน — ก็อยู่ในบทสนทนาแล้ว ข้างเบอร์ที่ตรวจพบในนั้น ลูกค้าที่เชื่อมไว้พร้อมออร์เดอร์ล่าสุด และสิ่งที่ระบบของคุณรายงาน ข้อมูลเป็นปัจจุบันเพราะได้มาจากการอนุมาน ไม่ใช่เพราะมีคนจำได้ว่าต้องอัปเดต

### แสดงข้อมูลจาก CRM หรือระบบออร์เดอร์ของเราได้ไหม?

ได้ คุณชี้ไปที่ HTTP endpoint ที่คุณควบคุม เราส่งตัวระบุที่เรามี — บทสนทนา ช่องทาง external id เบอร์โทร อีเมล ชื่อ แอตทริบิวต์ที่กำหนดเอง — และ endpoint ของคุณตอบกลับเป็นรายการไทม์ไลน์ที่มันรู้จัก: ออร์เดอร์ การโทร การเข้าชมเว็บ โดยค่าเริ่มต้นจะไม่มีอะไรถูกคัดลอกเข้าฐานข้อมูลของเรา เพียงดึงมาแสดง แหล่งลูกค้าในโหมดเชื่อมต่อยังแสดงชื่อ เบอร์โทร และอีเมลของคนนั้นได้ โดยอ่านสดเมื่อเปิดบทสนทนา

### เอเจนต์ AI ใช้ข้อมูลภายนอกนั้นตอนตอบได้ไหม?

เฉพาะเมื่อคุณเปิดสำหรับแหล่งนั้นและเก็บสำเนาแคชไว้ เอเจนต์อ่านบริบทภายนอกจากแคชนั้น แทนที่จะให้ endpoint ของคุณตอบทุกข้อความ — API ภายในที่ช้าหรือถูกจำกัดอัตราจึงไม่เคยทำให้การตอบลูกค้าล่าช้า

### นำเข้าลูกค้าที่เรามีอยู่แล้วได้ไหม?

ได้ — จากสเปรดชีตด้วยการจับคู่คอลัมน์ที่ตั้งครั้งเดียวแล้วระบบจำไว้ หรือจากแหล่ง HTTP ที่ซิงก์แบบ cursor เพื่อให้แต่ละรอบทำต่อจากจุดที่รอบก่อนหยุด แต่ละแถวอิงรหัสลูกค้าของคุณเอง การนำเข้าซ้ำจึงอัปเดตลูกค้าคนเดิม แทนที่จะเพิ่มสำเนาที่สอง

### ใครเห็นข้อมูลลูกค้าได้บ้าง?

ข้อมูลลูกค้าถูกควบคุมด้วยระบบสิทธิ์ของ workspace และการกั้นนี้บังคับใช้ทั้งที่ฐานข้อมูลและ API — สมาชิกที่ไม่มีสิทธิ์จะอ่านข้อมูลไม่ได้ไม่ว่าทางใด สิทธิ์ระดับช่องทางมีผลซ้อนอีกชั้น: ประวัติจากช่องทางที่พนักงานเปิดไม่ได้จะไม่มีวันปรากฏในบทสนทนาของเขา

### ถ้าคนเดียวกันทักมาจากสองช่องทางจะเป็นอย่างไร?

ข้อความจากอีกช่องทางจะปรากฏในบทสนทนาที่คุณเปิดอยู่ โดยจับคู่ด้วยเบอร์โทรหรืออีเมลที่ใช้ร่วมกัน ขณะที่สองบทสนทนายังแยกกัน ไม่มีการเดาจากชื่อที่คล้ายกัน — ถ้าไม่มีตัวระบุร่วมก็จะแยกกันอยู่ เมื่อคุณเชื่อมบทสนทนากับลูกค้า การจับคู่จะอิงการเชื่อมนั้นแทนเบอร์โทร และหากสองช่องทางเป็นบัญชีเดียวกันจริง ๆ ก็รวมทั้งช่องทางเข้ากับอีกช่องทางได้
