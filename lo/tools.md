## ໃຫ້ຕົວແທນມີເຄື່ອງມືໃນສາມຂັ້ນຕອນ

ເລືອກມັນ, ເຊື່ອມມັນ, ໃຫ້ສິດມັນ.

1. **ເລືອກປະເພດ** — ເລືອກຈາກແຄັດຕາລັອກມີໃນຕົວ, ຫຼື ສ້າງ webhook, ຟັງຊັນ Python, ການເຊື່ອມຕໍ່ MCP ຫຼື ຕົວແທນເປັນເຄື່ອງມື.
2. **ເຊື່ອມຕໍ່ມັນ** — ວາງ API key ທີ່ຜູ້ໃຫ້ບໍລິການໃຫ້ທ່ານ, ຫຼື URL ແລະ auth ຂອງບໍລິການຂອງທ່ານເອງ. ຂໍ້ມູນເຂົ້າລະບົບຖືກເກັບແບບເຂົ້າລະຫັດ.
3. **ໃຫ້ສິດມັນ** — ເປີດໃຫ້ຕົວແທນທີ່ຄວນໃຊ້, ຫຼື ຕັ້ງເປັນທົ່ວໄປໃຫ້ທຸກຕົວແທນ. ຕົວແທນຕັດສິນເອງວ່າຈະເອີ້ນມັນເມື່ອໃດ ຈາກຄຳອະທິບາຍຂອງເຄື່ອງມື.

## ຫ້າປະເພດເຄື່ອງມື, ລາຍການດຽວ

ບໍ່ວ່າຕົວແທນຕ້ອງເອື້ອມໄປຫາຫຍັງ, ມີວິທີໜຶ່ງໃນນີ້ຮອງຮັບຢູ່ແລ້ວ.

### ຫົກສິບເຄື່ອງມື, ພ້ອມໃຊ້

ຄົ້ນຫາເວັບ, Wikipedia ແລະ ArXiv, ບຣາວເຊີແບບ headless, Gmail ແລະ Google Calendar, GitHub, Telegram, text-to-speech, ບອດ BI ແລະ Drive ຂອງທ່ານເອງ — ແຕ່ລະອັນເປັນກາດໃນແຄັດຕາລັອກ, ຫຼາຍອັນເຮັດວຽກໄດ້ທັນທີທີ່ທ່ານເພີ່ມມັນ.

### HTTP API ໃດກໍໄດ້

ອະທິບາຍ endpoint — method, URL, header, auth ແລະ JSON ທີ່ຕົວແທນຄວນສົ່ງ — ແລ້ວມັນກາຍເປັນເຄື່ອງມື. GET, POST, PUT, PATCH ແລະ DELETE, ດ້ວຍ bearer token ຫຼື API key.

### Python ຂອງທ່ານເອງ

ຂຽນຟັງຊັນ, ໃຫ້ input schema, ແລ້ວມັນຮັນໃນ sandbox ພ້ອມ timeout — ອອບໄລນ໌ ຍົກເວັ້ນທ່ານອະນຸຍາດອິນເຕີເນັດ.

### MCP server ໃດກໍໄດ້

ຊີ້ໄປທີ່ URL ຂອງ server ແລ້ວເຄື່ອງມືທີ່ມັນເປີດຈະຖືກຄົ້ນພົບໃຫ້ທ່ານ. ເປີດ ຫຼື ປິດແຕ່ລະອັນ, ແລະ ໃຫ້ຕ້ອງອະນຸມັດສຳລັບອັນທີ່ຂຽນຂໍ້ມູນ.

### ຕົວແທນເປັນເຄື່ອງມື

ເປີດຕົວແທນໜຶ່ງໃຫ້ອີກຕົວແທນໃຊ້: ນັກຂຽນຖາມນັກຄົ້ນຄວ້າໄດ້, ຕົວແທນຂາຍຖາມຄົນກວດສະຕັອກໄດ້ — ແຕ່ລະຕົວຍັງຮັກສາພຣອມ, ໂມເດວ ແລະ ເຄື່ອງມືຂອງຕົນເອງ.

### ທ່ານຕັດສິນວ່າໃຜຖືອັນໃດ

ໃຫ້ສິດເຄື່ອງມືຕໍ່ຕົວແທນ ຫຼື ຕັ້ງເປັນທົ່ວໄປ, ປິດມັນໂດຍບໍ່ຕ້ອງລຶບ, ແຄຊຜົນລັບຂອງມັນ, ແລະ ໃຫ້ຕ້ອງມີການອະນຸມັດຈາກຄົນກ່ອນມັນຈະຮັນ.

## ແຕ່ລະປະເພດຕ້ອງການຫຍັງ

ຊ່ອງຂໍ້ມູນ, ຕົວເລືອກ ແລະ ຂໍ້ຈຳກັດ — ກ່ອນທ່ານສະໝັກ.

### ປະເພດເຄື່ອງມື

- Built-in — ເລືອກຈາກແຄັດຕາລັອກ
- Webhook — HTTP endpoint ໃດກໍໄດ້
- Code — ຟັງຊັນ Python ໃນ sandbox
- MCP — MCP server ໃດກໍໄດ້
- Agent as tool — ຕົວແທນອື່ນໃນພື້ນທີ່ເຮັດວຽກ

### ເຄື່ອງມື Webhook

- GET, POST, PUT, PATCH ແລະ DELETE
- ບໍ່ມີ auth, bearer token ຫຼື API key
- Header ກຳນົດເອງ
- JSON input schema ທີ່ຕົວແທນຕື່ມໃຫ້

### ເຄື່ອງມື Code

- Python, ແກ້ໄຂຢູ່ໃນບຣາວເຊີ
- ຮັນໃນ sandbox ພ້ອມ timeout
- ການເຂົ້າອິນເຕີເນັດປິດຢູ່ ຍົກເວັ້ນທ່ານອະນຸຍາດ
- Input schema, ຄືກັບເຄື່ອງມືອື່ນ

### MCP server

- ເຊື່ອມຕໍ່ດ້ວຍ URL, ຜ່ານ SSE ຫຼື Streamable HTTP
- Auth ແບບ bearer token ແລະ header ກຳນົດເອງ
- ເຄື່ອງມືທີ່ຄົ້ນພົບ ລິດເປັນລາຍການ
- ແຕ່ລະອັນເປີດ ຫຼື ປິດແຍກກັນ
- ອະນຸມັດຕໍ່ເຄື່ອງມື, ຫຼື ຕໍ່ທັງໝົດ

## ຄຳຖາມກ່ຽວກັບເຄື່ອງມື

ສິ່ງທີ່ຄົນຖາມ ກ່ອນເຊື່ອມລະບົບທຳອິດ.

### ມີເຄື່ອງມືມີໃນຕົວຈັກອັນ?

ຫົກສິບອັນມື້ນີ້, ຈັດເປັນການຄົ້ນຫາ, ຄວາມຮູ້, ການປະມວນຜົນ, ຂໍ້ມູນ, AI ແລະ media, ການເງິນ, ອຳນວຍຄວາມສະດວກ, ຜະລິດຕະພາບ, MCP server, Drive ແລະ ການເຊື່ອມຕໍ່ — ລາຍການເຕັມຢູ່ໜ້ານີ້. ນອກເໜືອຈາກນັ້ນ, HTTP API, ຟັງຊັນ Python ຫຼື MCP server ໃດກໍໄດ້ ກາຍເປັນເຄື່ອງມືໄດ້.

### ຕ້ອງມີ API key ບໍ່?

ບາງເຄື່ອງມືຕ້ອງການ key ຂອງຜູ້ໃຫ້ບໍລິການ — Tavily, Serper, Gmail, GitHub ແລະ ອື່ນໆທີ່ມີໄອຄອນກະແຈ. ຫຼາຍອັນເຮັດວຽກໄດ້ໂດຍບໍ່ຕ້ອງມີ, ລວມທັງ DuckDuckGo, Wikipedia, ArXiv, Web Fetch, ບຣາວເຊີ Playwright ແລະ ເຄື່ອງມື Drive.

### ເຄື່ອງມືລໍຖ້າອະນຸມັດກ່ອນຮັນໄດ້ບໍ່?

ໄດ້. ເປີດ Require human approval ສຳລັບເຄື່ອງມືທີ່ຄວນໃຫ້ຄົນຢືນຢັນ — ໂດຍທົ່ວໄປແມ່ນອັນທີ່ສົ່ງ, ຂຽນ ຫຼື ລຶບ — ແລ້ວການຮັນຂອງຕົວແທນຈະຢຸດຈົນກວ່າໃຜຈະອະນຸມັດການເອີ້ນນັ້ນ. ສຳລັບ MCP server ຫຼື ການເຊື່ອມຕໍ່, ການອະນຸມັດຕັ້ງຕໍ່ເຄື່ອງມືທີ່ຄົ້ນພົບແຕ່ລະອັນ.

### ເຊື່ອມ MCP server ຂອງຕົນເອງໄດ້ບໍ່?

ໄດ້. ເພີ່ມເຄື່ອງມື MCP ດ້ວຍ URL, transport ແລະ auth ຂອງ server; ເຄື່ອງມືທີ່ມັນເປີດຈະຖືກຄົ້ນພົບ ແລະ ລິດເປັນລາຍການ, ແລ້ວທ່ານເປີດ ຫຼື ປິດແຕ່ລະອັນ. ມີ preset ໃຫ້ N8N, Slack, Notion, GitHub, Google Drive ແລະ WordPress ຢູ່ໃນແຄັດຕາລັອກ.

### ຕົວແທນໜຶ່ງໃຊ້ຕົວແທນອື່ນເປັນເຄື່ອງມືໄດ້ບໍ່?

ໄດ້. ສ້າງ Agent as tool ແລ້ວເລືອກຕົວແທນ. ຕົວແທນໃດທີ່ໄດ້ຮັບສິດ ກໍມອບວຽກໃຫ້ ແລະ ໃຊ້ຄຳຕອບໄດ້, ໃນຂະນະທີ່ຕົວແທນນັ້ນຍັງຮັກສາພຣອມ, ໂມເດວ ແລະ ເຄື່ອງມືຂອງຕົນເອງ.

### Viettel Post ແລະ KiotViet ຢູ່ໃສ?

ພວກມັນເປັນການເຊື່ອມຕໍ່ມີໃນຕົວ. ເຊື່ອມບັນຊີຂອງທ່ານຄັ້ງດຽວ ແລ້ວຕົວແທນຈະໄດ້ຮັບການດຳເນີນການຂອງມັນເປັນເຄື່ອງມື — ຄິດຄ່າສົ່ງ, ສ້າງການສົ່ງ, ກວດສະຕັອກ, ຄົ້ນຫາຄຳສັ່ງຊື້.
