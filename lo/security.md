# ຄວາມປອດໄພ ແລະ ການກຳກັບ ສຳລັບຕົວແທນ AI

## ໃຫ້ແຕ່ລະຄົນ ມີສິດເທົ່າທີ່ຕ້ອງການແທ້

ສິດແຍກຕາມຊັບພະຍາກອນ, ສິດເຂົ້າຊ່ອງທາງຕາມທີມ, ຂໍ້ມູນເຂົ້າລະບົບທີ່ເຂົ້າລະຫັດ, ຮາວກັນກຳນົດສິ່ງທີ່ຕົວແທນເວົ້າໄດ້, ແລະ ບັນທຶກທຸກຮອບການເຮັດວຽກ — ການນຳ AI ມາຢູ່ຕໍ່ໜ້າລູກຄ້າ ຈຶ່ງເປັນການຕັດສິນໃຈທີ່ທ່ານອະທິບາຍໄດ້.

## ການກຳກັບທີ່ຍັງໃຊ້ໄດ້ ເມື່ອມີທີມທີສອງ

ການຄວບຄຸມທີ່ຕັດສິນວ່າ AI ຈະໄດ້ຮັບຄວາມໄວ້ວາງໃຈໃຫ້ລົມກັບລູກຄ້າແທ້ໄດ້ບໍ່.

### ບົດບາດທີ່ເໝາະກັບໜ້າທີ່

ເຈົ້າຂອງ, ຜູ້ດູແລ ແລະ ສະມາຊິກ ມີໃຫ້ພ້ອມໃຊ້, ແລະ ບົດບາດກຳນົດເອງ ເມື່ອສາມອັນນັ້ນບໍ່ເໝາະ. ສິດມອບໃຫ້ຕໍ່ຊັບພະຍາກອນ ແລະ ຕໍ່ການກະທຳ, “ດູແລກ່ອງຂໍ້ຄວາມ, ບໍ່ເຄີຍເຫັນການເກັບເງິນ” ຈຶ່ງເປັນບົດບາດ ບໍ່ແມ່ນກົດທີ່ຕ້ອງມີຄົນຈື່.

### ການແບ່ງປັນຕາມຊັບພະຍາກອນ

ຕົວແທນ, ເອກະສານ, ໂຟນເດີ, ເຄື່ອງມື ຫຼື ບອດ ມີລາຍການສິດເຂົ້າເຖິງຂອງຕົນເອງເທິງບົດບາດ — ເບິ່ງ, ໃຊ້, ແກ້ໄຂ ຫຼື ຈັດການ (ສຳລັບເອກະສານ: ເບິ່ງ, ຄອມເມັນ ຫຼື ແກ້ໄຂ), ໃຫ້ແກ່ສະມາຊິກ, ທີມ ຫຼື ທຸກຄົນ.

### ແຍກຕາມຊ່ອງທາງ

ຊ່ອງທາງປິດໄວ້ຕາມຄ່າເລີ່ມຕົ້ນ. ມອບ Page, ບັນຊີ Zalo ຫຼື widget ໃຫ້ສະມາຊິກ, ບົດບາດ ຫຼື ທີມ ໃນລະດັບ ເບິ່ງ, ຕອບ, ກຳນົດຄ່າ ຫຼື ສິດເຕັມ, ແລ້ວກ່ອງຂໍ້ຄວາມທີ່ເຂົາເປີດຈະມີແຕ່ການສົນທະນາເຫຼົ່ານັ້ນ — ສິ່ງທີ່ເອເຈນຊີຕ້ອງການ ແລະ ສິ່ງທີ່ທີມຊ່ວຍເຫຼືອຂອງສິນຄ້າໜຶ່ງຕ້ອງການ.

### ຄວາມລັບທີ່ເປັນຄວາມລັບແທ້

ຂໍ້ມູນເຂົ້າລະບົບຖານຂໍ້ມູນ, token ຂອງຊ່ອງທາງ ແລະ auth header ຂອງ endpoint ຖືກເຂົ້າລະຫັດຂະນະຈັດເກັບ ແລະ ບໍ່ເຄີຍສົ່ງກັບໄປບຣາວເຊີ. ແບບຟອມບອກພຽງວ່າໄດ້ຕັ້ງຄ່າຄວາມລັບແລ້ວ; ມັນບໍ່ສະແດງຄ່ານັ້ນອີກ.

### ຮາວກັນ ກຳນົດສິ່ງທີ່ຕົວແທນເວົ້າໄດ້

ນະໂຍບາຍທີ່ໃຊ້ກັບສິ່ງທີ່ເຂົ້າ ແລະ ອອກຈາກຕົວແທນ, ພ້ອມບັນທຶກກວດສອບວ່າຮາວກັນໃດເຮັດວຽກ, ມັນເຮັດຫຍັງ ແລະ ເປັນຫຍັງ — ຄຳຕອບທີ່ຖືກບລັອກຈຶ່ງເປັນບັນທຶກ ບໍ່ແມ່ນປິດສະໜາ.

### ບັນທຶກສຳລັບການເຮັດວຽກທຸກປະເພດ

ການເຮັດວຽກຂອງຕົວແທນພ້ອມການເອີ້ນເຄື່ອງມື ແລະ ຄ່າໃຊ້ຈ່າຍ, ການແລ່ນວຽກຕາມກຳນົດເວລາ, ການສົ່ງເວັບຮຸກ, ການສົ່ງຂໍ້ຄວາມດູແລ, ຂໍ້ຜິດພາດຂອງແພລດຟອມ ແລະ ທຸກການປ່ຽນແປງສິດເຂົ້າເຖິງ — ແຕ່ລະຢ່າງມີລາຍການຂອງຕົນເອງ ແທນທີ່ຈະລວມເປັນກະແສດຽວ.

## ສິ່ງທີ່ທ່ານຄວບຄຸມໄດ້

ສິດເຂົ້າເຖິງ, ການຈັດການຂໍ້ມູນ, ການມອງເຫັນ ແລະ ຄວາມຕໍ່ເນື່ອງ.

### ຕົວຕົນ ແລະ ສິດເຂົ້າເຖິງ

- ບົດບາດລະບົບ ເຈົ້າຂອງ, ຜູ້ດູແລ ແລະ ສະມາຊິກ
- ບົດບາດກຳນົດເອງ ພ້ອມສິດແຍກຕາມຊັບພະຍາກອນ ແລະ ການກະທຳ
- ທີມ, ພ້ອມຫົວໜ້າ ແລະ ສະມາຊິກ
- 55 ຊັບພະຍາກອນສິດ, 201 ສິດ
- ຄຳເຊີນ, ແລະ ຖອນສິດໄດ້ຈາກໜ້າຈໍດຽວ

### ການແບ່ງປັນລະດັບຊັບພະຍາກອນ

- ເບິ່ງ, ໃຊ້, ແກ້ໄຂ, ຈັດການ — ສຳລັບເອກະສານ: ເບິ່ງ, ຄອມເມັນ, ແກ້ໄຂ
- ມອບໃຫ້ສະມາຊິກ, ທີມ ຫຼື ທັງພື້ນທີ່ເຮັດວຽກ
- ໃຊ້ກັບຕົວແທນ, ເອກະສານ, ໂຟນເດີ ແລະ ເຄື່ອງມື
- ໃຊ້ກັບຖານຄວາມຮູ້, ຊ່ອງທາງ, ແຫຼ່ງຂໍ້ມູນ ແລະ ບອດ
- ເອກະສານແບ່ງປັນດ້ວຍລິ້ງ, ຕາມລະດັບທີ່ທ່ານເລືອກ

### ການຈັດການຂໍ້ມູນ

- ແຍກພື້ນທີ່ເຮັດວຽກອອກຈາກກັນ ໃນທຸກຄຳຂໍ
- ຂໍ້ມູນເຂົ້າລະບົບເຂົ້າລະຫັດຂະນະຈັດເກັບ
- ຄວາມລັບບໍ່ເຄີຍສົ່ງກັບໄປບຣາວເຊີ
- ການເຊື່ອມຕໍ່ຖານຂໍ້ມູນແບບອ່ານຢ່າງດຽວ ເມື່ອທ່ານຕ້ອງການ
- ຂໍ້ມູນລູກຄ້າພາຍນອກຖືກດຶງມາສະແດງ, ບໍ່ໄດ້ກັອບປີ້ແບບງຽບໆ

### ການມອງເຫັນ

- ບັນທຶກການເຮັດວຽກທຸກຮອບ ພ້ອມໂທເຄັນ ແລະ ຄ່າໃຊ້ຈ່າຍ
- ກວດສອບຮາວກັນ — ອັນໃດເຮັດວຽກ, ແລະ ມັນເຮັດຫຍັງ
- ປະຫວັດການເຮັດວຽກຕາມກຳນົດເວລາ
- ບັນທຶກການສົ່ງ webhook
- ບັນທຶກຂໍ້ຜິດພາດຂອງແພລດຟອມ ແລະ ບັນທຶກສິດເຂົ້າເຖິງສຳລັບທຸກການປ່ຽນແປງບົດບາດ ແລະ ການແບ່ງປັນ

### ການສຳຮອງ ແລະ ຄວາມຕໍ່ເນື່ອງ

- ສຳຮອງຕາມຕ້ອງການ ແລະ ຕາມກຳນົດເວລາ
- ກູ້ຄືນເຂົ້າພື້ນທີ່ເຮັດວຽກ
- ສົ່ງອອກຂໍ້ມູນພື້ນທີ່ເຮັດວຽກ
- ເຫັນການໃຊ້ບ່ອນເກັບຂໍ້ມູນ ຕໍ່ພື້ນທີ່ເຮັດວຽກ

### ການເຂົ້າເຖິງແບບໂປຣແກຣມ

## ຄຳຖາມກ່ຽວກັບຄວາມປອດໄພ ແລະ ການກຳກັບ

ສິ່ງທີ່ຜູ້ດູແລລະບົບກວດ ກ່ອນເຊີນທີມທີສອງເຂົ້າມາ.

### ສິດລະອຽດແຄ່ໃດ?

ສິດຖືກໃຫ້ຕາມປະເພດຊັບພະຍາກອນ ແລະ ຕາມການກະທຳ — ອ່ານຕົວແທນ, ສ້າງເຄື່ອງມື, ກູ້ຄືນການສຳຮອງ, ເລີ່ມການຝຶກ: 55 ຊັບພະຍາກອນ ແລະ 201 ສິດ, ແຕ່ລະສິດແຍກກັນ. ມີສາມບົດບາດພ້ອມໃຊ້ (ເຈົ້າຂອງ, ຜູ້ດູແລ, ສະມາຊິກ) ແລະ ທ່ານສາມາດສ້າງບົດບາດເອງ, ເລີ່ມຈາກວ່າງເປົ່າ ຫຼື ສຳເນົາຈາກບົດບາດທີ່ມີ, ດັ່ງນັ້ນ “ຕອບກ່ອງຂໍ້ຄວາມໄດ້ ແຕ່ແຕະການເກັບເງິນບໍ່ໄດ້” ກາຍເປັນບົດບາດໜຶ່ງ ບໍ່ແມ່ນຂໍ້ຍົກເວັ້ນທີ່ໃຜຕ້ອງຈື່.

### ແບ່ງປັນຕົວແທນ ຫຼື ເອກະສານດຽວ ໂດຍບໍ່ແບ່ງປັນພື້ນທີ່ເຮັດວຽກໄດ້ບໍ່?

ໄດ້. ນອກຈາກສິດຕາມບົດບາດ, ແຕ່ລະຊັບພະຍາກອນ — ຕົວແທນ, ເອກະສານ, ໂຟນເດີ, ເຄື່ອງມື, ຄັງຄວາມຮູ້, ຊ່ອງທາງ, ແຫຼ່ງຂໍ້ມູນ ແລະ ບອດ — ມີລາຍການສິດເຂົ້າເຖິງຂອງຕົນເອງ. ທ່ານໃຫ້ລະດັບແກ່ສະມາຊິກ, ທີມ ຫຼື ທັງ workspace ໃນສິ່ງນັ້ນໂດຍສະເພາະ: ເບິ່ງ, ໃຊ້, ແກ້ໄຂ ຫຼື ຈັດການ ສຳລັບຕົວແທນ, ເຄື່ອງມື ຫຼື ບອດ; ເບິ່ງ, ຄອມເມັນ ຫຼື ແກ້ໄຂ ສຳລັບເອກະສານ ຫຼື ໂຟນເດີ.

### ເອເຈນຊີໃຫ້ທີມລູກຄ້າເຂົ້າເຖິງສະເພາະຊ່ອງທາງຂອງເຂົາໄດ້ບໍ່?

ນັ້ນແມ່ນຈຸດປະສົງຂອງສິດເຂົ້າເຖິງຊ່ອງທາງ. ຊ່ອງທາງປິດໄວ້ຕາມຄ່າເລີ່ມຕົ້ນ: Page, ບັນຊີ Zalo ຫຼື widget ຖືກມອບໃຫ້ສະມາຊິກ, ບົດບາດ ຫຼື ທີມ ໃນລະດັບ ເບິ່ງ, ຕອບ, ກຳນົດຄ່າ ຫຼື ສິດເຕັມ, ແລະ ກ່ອງຂໍ້ຄວາມທີ່ເຂົາເປີດຈະມີແຕ່ການສົນທະນາຈາກສິ່ງທີ່ເຂົາຖື. ເຈົ້າຂອງ ແລະ ຜູ້ດູແລເຫັນທຸກຊ່ອງທາງ. ເພື່ອຕອບລູກຄ້າ ຕ້ອງມີທັງສອງເຄິ່ງ — ສິດຕອບຢູ່ບົດບາດ ແລະ ລະດັບຕອບຢູ່ຊ່ອງທາງນັ້ນ.

### ຂໍ້ມູນເຂົ້າລະບົບ ແລະ API token ເກັບໄວ້ບ່ອນໃດ?

ເຂົ້າລະຫັດຂະນະຈັດເກັບ, ແລະ ບໍ່ເຄີຍສົ່ງກັບໄປບຣາວເຊີ. ແບບຟອມຕັ້ງຄ່າທີ່ສະແດງການເຊື່ອມຕໍ່ ບອກພຽງວ່າໄດ້ຕັ້ງຄ່າຄວາມລັບແລ້ວ; ມັນບໍ່ສະແດງຄ່ານັ້ນອີກ. ສິ່ງນີ້ໃຊ້ກັບການເຊື່ອມຕໍ່ຖານຂໍ້ມູນ, token ຂອງຊ່ອງທາງ ແລະ auth header ຂອງ endpoint ເສີມຂໍ້ມູນ ເໝືອນກັນ.

### ຂ້ອຍເຫັນຫຍັງໄດ້ແດ່ ກ່ຽວກັບສິ່ງທີ່ AI ເຮັດແທ້?

ທຸກຮອບຖືກບັນທຶກຕັ້ງແຕ່ຕົ້ນຈົນຈົບ: ຂໍ້ຄວາມ, ເຄື່ອງມືທີ່ມັນເອີ້ນ ແລະ ສິ່ງທີ່ສົ່ງກັບມາ, ໂທເຄັນ ແລະ ຄ່າໃຊ້ຈ່າຍຕໍ່ຂັ້ນຕອນ, ແລະ ຮາວກັນໃດເຮັດວຽກ ແລະ ມັນເຮັດຫຍັງ. ມີບັນທຶກແຍກສຳລັບການເຮັດວຽກຕາມກຳນົດເວລາ, ການສົ່ງ webhook, ການສົ່ງຂໍ້ຄວາມ Care ແລະ ຂໍ້ຜິດພາດຂອງແພລດຟອມ.

### ຂ້ອຍເອົາຂໍ້ມູນອອກໄດ້ບໍ່, ແລະ ລຶບມັນໄດ້ບໍ່?

ການສຳຮອງລັນໄດ້ຕາມຕ້ອງການ ຫຼື ຕາມກຳນົດເວລາ ແລະ ກູ້ຄືນເຂົ້າພື້ນທີ່ເຮັດວຽກໄດ້. ການລຶບເປັນການກະທຳຫຼັກ ບໍ່ແມ່ນຄຳຮ້ອງຫາຝ່າຍຊ່ວຍເຫຼືອ: ສະມາຊິກລຶບບັນຊີຂອງຕົນເອງໄດ້ຈາກເວັບໄຊ, ແລະ ຂໍ້ມູນພື້ນທີ່ເຮັດວຽກຈະຖືກລຶບໄປພ້ອມກັບພື້ນທີ່ເຮັດວຽກ.
